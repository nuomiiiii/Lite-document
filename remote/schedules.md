# 定时任务

定时任务用于在选定的服务器上定期执行命令。入口位于后台“远程管理 → 定时任务”，适用于 Lite `2.3.7`，推荐配套 Lite-agent `2.3.6.0`。

任务由 Lite 服务端调度，保存并启用后无需保持浏览器打开，也不需要在节点上另外配置系统定时任务。命令以 Agent 的运行账户执行，操作权限与[远程执行](/remote/terminal#重新验证)相同。

## 使用条件

- 在“系统设置 → 通用”中开启“允许远程管理”。
- 目标节点使用兼容的 Lite-agent，并在本地通过 `--enable-remote-control` 开启远程控制。
- 管理员已登录；新建、编辑、启用任务或立即执行时，按提示完成身份验证。

验证可以使用通行密钥；已启用 2FA 时输入当前验证码，未启用时输入管理员密码。同一页面内未过期的身份确认可继续使用，刷新后需要重新验证。任务成功保存后，后续自动执行不依赖这份短期授权或浏览器登录会话。

## 新建任务

1. 打开“远程管理 → 定时任务”，点击“新建定时任务”。
2. 填写名称和命令。命令可以手动输入，也可以从已保存的命令中选择。
3. 选择“定时方式”，填写间隔或日期、星期和时间。
4. 选择至少一台服务器，可按在线状态、国家/地区、分组和搜索条件筛选后批量选择。
5. 确认“启用”开关，完成身份验证并点击“保存”。保存后在任务卡片查看下次执行时间。

新任务默认启用，默认定时方式为每天北京时间 `03:00`；保存前应改成需要的时间。关闭“启用”可先保存配置，之后再手动启用。

### 定时方式

| 方式 | 配置 | 执行规则 |
| --- | --- | --- |
| 每隔 | 整数分钟或天，范围为 1 分钟至 30 天 | 保存或重新启用后，等待一个完整间隔再执行 |
| 每天 | 24 小时制时间，如 `03:00` | 每天按指定时间执行 |
| 每周 | 选择一个或多个星期，再指定时间 | 在每个选定的星期执行 |
| 每月 | 选择 1–31 日，再指定时间 | 当月没有指定日期时，改在当月最后一天执行 |

每天、每周和每月均按北京时间（`Asia/Shanghai`）计算，任务卡片和执行日志也按北京时间显示，不随浏览器、容器或服务器系统时区变化。例如每月 31 日的任务，在 4 月会于 30 日执行。

编辑并保存任务或重新启用任务，会重新计算下一次执行时间。列表中的拖动排序只改变展示顺序，不改变任务的执行时间或先后依赖。

### 数量与输入限制

| 项目 | 限制 |
| --- | --- |
| 全站定时任务 | 最多 30 个，包含已停用任务 |
| 每个任务的服务器 | 1–100 台 |
| 任务名称 | 最多 64 个字符 |
| 命令 | 非空，最多 64 KiB |

## 任务列表与立即执行

任务卡片显示启用状态、定时方式、命令、所选服务器、上次自动调度与下次执行时间，以及最近一次执行情况。可按任务名搜索、分页查看；清空搜索后可拖动卡片调整顺序。

| 操作 | 效果 |
| --- | --- |
| 立即执行 | 对保存的命令和节点发起一次执行，不改变下次定时时间，也不会自动启用已停用任务 |
| 编辑 | 修改名称、命令、节点和定时配置，保存前需要身份确认 |
| 关闭“启用” | 停止后续自动执行，并取消尚未交给 Agent 的排队命令 |
| 重新启用 | 完成身份确认后，按当前时间重新计算下一次执行 |
| 删除 | 删除任务及关联执行日志和输出，并移除尚未交给 Agent 的排队命令 |

已经交给 Agent 的命令可能继续执行，停用或删除任务不会撤销已产生的修改。需要停止这些进程时，应到对应节点处理。

## 执行日志

点击任务名称进入详情，查看“执行日志”。选择一次记录后，可查看各服务器的输出和退出码；记录和节点结果都支持分页。

| 显示 | 含义 |
| --- | --- |
| 已下发 | 命令已交给当前连接，最终执行结果仍需查看节点输出和退出码 |
| 排队 | 节点仍被判为在线，命令等待通过协议通道投递 |
| 离线 | 本次不会向该节点投递，节点恢复在线后也不会补发这次命令 |
| 未执行 | 节点不允许远程控制、版本不兼容、节点不存在或投递失败 |
| 上一次还在执行，这次已跳过 | 同一任务仍有未完成结果，本轮自动执行跳过 |

自动调度不会让同一任务的多轮执行重叠；只要上一次仍有未完成结果，后续定时轮次会继续跳过。手动“立即执行”会另发起一次执行，点击前应确认上一次是否仍在运行。

详情最多展示最近 50 次执行记录。后台保留最近 50 次已结束记录，并保留尚未结束的执行。后台“日志”页同时记录任务保存、执行、停用和删除操作。

## 停用与恢复

| 场景 | 任务行为 |
| --- | --- |
| 关闭页面、退出登录或删除登录会话 | 已启用任务继续按计划执行 |
| Lite 正常重启 | 保留已保存的任务；服务恢复后继续调度 |
| 修改任务所属管理员的密码或 2FA 等账号安全信息 | 相关任务自动停用，重新启用需要身份确认 |
| 关闭站点“允许远程管理” | 全部任务停用，并取消未交给 Agent 的排队命令 |
| 重新打开站点远程管理 | 不会自动恢复任务，需要逐个确认并启用 |

Lite 停机期间不会执行任务。重启后，已经到期的任务最多触发一轮，再从当前时间计算下次执行，不会把停机期间每个错过的轮次逐一补跑。

## 常见问题

| 问题 | 检查方式 |
| --- | --- |
| 到时间却没有输出 | 检查任务是否启用、节点是否在线和允许远程控制，再查看本轮日志是否跳过或未执行 |
| 每次都显示上一次还在执行 | 查看上一轮各节点结果，确认命令是否仍在运行或结果尚未返回 |
| 显示账户安全变更或远程管理关闭后已停用 | 检查站点开关与任务配置，再完成身份确认并重新启用 |
| 执行时间与预期差几个小时 | 定时任务统一使用北京时间，按该时区重新核对配置 |
