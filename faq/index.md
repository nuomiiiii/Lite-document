# 常见问题

## 页面能打开，终端为什么 403？

普通页面和终端不是同一连接。先确认站点“允许远程管理”和 Agent 本地远程控制都已开启，再完成页面要求的 TOTP 或管理员密码验证。仍然返回 403 时，检查登录会话、Agent 版本、反向代理的 Upgrade 头、Origin 和 Cloudflare Access。

## 为什么换证书后 Agent 403？

检查 Agent endpoint 是否改到了另一端口或实例，以及代理是否把请求送到错误后端。

## Agent 进程仍在运行，为什么面板显示离线？

先按[版本与功能范围](/guide/versioning)核对 Lite 与 Lite-agent 是否为兼容组合。两端需要同时更新：服务端负责维持在线判定，Agent 通过心跳、读超时和快速重连恢复中断连接。

版本已经正确仍反复离线时，继续检查反向代理 WebSocket 超时、Cloudflare Access、DNS 和 IPv4/IPv6 路径。状态与日志命令见 [Agent 安装与维护](/install/agent)。

## Agent 的状态、日志和卸载命令在哪里？

[Agent 安装与维护](/install/agent) 按 systemd、Docker、OpenRC、OpenWrt、Windows 和 macOS 分别列出了状态检查、日志、重启、更新和卸载命令；默认 systemd 安装还提供一键完全卸载。历史自动发现安装在迁移前需确认是否保留 `auto-discovery.json`；需要保留本地流量周期时，还应备份 `net_static.json`。

## 数据库一小时增加很多，是否代表一天线性增长？

不一定。新部署初期的增长速度不能直接乘以 24 或保留天数。长期占用还取决于服务器上报间隔、探测间隔、任务数、数据保留时间和数据波动。

## Agent 在线，为什么不能授权 MCP？

确认使用 Lite `2.3.3` 和 Lite-agent `2.3.3.0`，并同时开启站点“允许远程管理”“启用 MCP 代理”及 Agent 本地 `--enable-remote-control`。旧 Agent 可能仍能上报监控数据，但不具备 MCP 完整管理能力。操作步骤见[MCP 代理与 AI 授权](/remote/mcp)。

## MCP 新建授权没有客户端可选？

先在 AI 客户端添加后台给出的 MCP 服务地址并发起连接，再回到 Lite 选择待授权请求。“新建授权”不会生成通用 Token；站点 API Key 和 Agent 安装凭据也不能用于该连接。

## 重置 Token 后节点为什么离线？

原连接凭据已经失效。请在原节点“节点配置 → 部署指令”中重新复制完整命令并更新 Agent，不要继续使用保存过的旧命令，也无需删除节点。详见[重置 Token](/admin/servers#重置-token)。

## 每日流量明细相加，为什么不等于图表合计？

图表只汇总价格大于 0 的服务器；明细包含所有当前节点，并按各自的计费方式显示用量，包括免费及未配置价格的节点。两者的统计范围不同，详见[仪表盘](/admin/dashboard#最近一个月)。

## 为什么回收空间前后变化不大？

数据库可能仍有有效数据、WAL 或迁移临时页；空闲页也可能已被后续写入复用。先看主库、监控库、WAL 和 SHM 的总占用，再判断是否异常。

## 为什么 WAL 不变但主数据库变大？

检查点会把 WAL 页写回主文件。WAL 维持在一个工作大小、主文件增长是正常过程，应观察总占用和保留周期是否趋于稳定。

## 为什么关闭内置 HTTPS 后 HTTP 仍无法访问？

确认 HTTP 端口仍被容器映射并被防火墙允许。浏览器可能记住 HSTS，端口也可能仍写成 HTTPS 端口。直接检查 `http://主机:27777` 和后端启动日志。

## 为什么容器映射了 HTTPS 端口仍访问不了？

后台配置的 HTTPS 端口必须与容器内实际监听端口、映射右侧的容器端口一致。左侧宿主机端口可以不同，例如 `443:36888` 表示通过宿主机 `443` 访问容器的 `36888`。`127.0.0.1:443:36888` 只允许宿主机本地访问；VPN 客户端直连应绑定 VPN 地址或所有地址并配合防火墙。

## 旗帜没有显示为对应地区

输入 ISO 3166-1 两位代码，例如 `HK`、`US`、`JP`。主题需要支持该代码的旗帜映射；缺少 emoji 字体时应使用图标资源而不是依赖系统字符。

## 为什么新服务器没有套用离线或流量默认配置？

默认配置只作用于保存之后新加入的服务器，不会改写已有规则。延迟监测告警还要求该服务器已经被分配到延迟任务。保存默认配置前已经存在的节点需要手动补规则。

## 负载告警静默后，仪表盘为什么还在显示告警？

静默只暂停通知渠道消息。告警检测、当前告警、仪表盘、实时负载和监控图表继续显示真实状态。到期后自动恢复通知；永久静默需要手动解除。

## 启用内置 HTTPS 后，Linux 在线更新失败？

确认当前实例由官方脚本安装并通过 systemd 或 OpenWrt / iStoreOS 的 procd 管理，且主数据库和 SQLite 监控数据库都位于受管 `data` 目录。Docker、Windows、不支持的服务管理方式、外置指标数据库或不满足回退条件的目录布局不支持后台一键更新。具体检查项见[Linux 脚本安装](/install/linux#一键更新的限制)。

## 如何提交有效问题？

请同时提供：

- 版本号和七位构建码。
- Docker、脚本或二进制部署方式。
- CPU 架构、内存和数据库大小。
- 相关时间段的日志。
- 可复现步骤与浏览器控制台错误。

提交到 [nuomiiiii/lite Issues](https://github.com/nuomiiiii/lite/issues)。公开内容前先删除域名、IP、Tunnel 凭据和备份文件。
