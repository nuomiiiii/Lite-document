# 通知与告警

通知渠道、规则和报告分开配置。渠道负责把消息发出去；规则决定何时触发。

## Telegram JavaScript 模板

Lite 自带的通知渠道可以直接使用；需要 Telegram 品牌图、结构化消息和按告警类型跳转时，可按需使用这份可选模板：

<a href="../downloads/lite-telegram-notification.js" download>下载 Lite Telegram 通知 JS 模板</a>

使用前只需修改文件顶部的配置：

| 配置 | 填写内容 |
| --- | --- |
| `TG_TOKEN` | 由 Telegram BotFather 生成的 Bot Token |
| `TG_CHAT_ID` | 接收通知的会话或群组 ID |
| `PANEL_URL` | Lite 面板完整地址，例如 `https://status.example.com` |
| `PHOTO_URL` | 可公开访问的首图地址；不使用首图时可留空 |
| `SEND_BRAND_IMAGE` | `true` 发送首图，`false` 只发文本 |
| `TIME_ZONE_OFFSET` | 消息时间的 UTC 时区偏移，北京时间为 `8` |

配置后进入“系统设置 → 通知渠道”，选择 `JavaScript`，将整份脚本粘贴到“JavaScript 代码”并保存，最后使用测试发送确认 Bot、会话 ID 和面板链接均可用。脚本会根据通知类型跳转到服务器概览、用量统计、对应服务器的网络监测视图、回程线路或账单页面；日报、周报和月报跳转到仪表盘。延迟监测告警会保留「延迟异常」或「丢包异常」标题，各项之间换行显示。延迟异常消息不展示允许上浮、允许下浮和成功样本。下载模板中的配置项默认留空，填写自己的值后再粘贴到后台。

::: warning 保护 Bot Token
JavaScript 模板会保存 Bot Token。只在自己管理的 Lite 实例中使用，不要把填过 Token 的脚本发布到公开仓库或发给他人。
:::

## 新服务器默认配置

进入对应通知页面后，使用“默认配置”：

- 离线通知：为新服务器启用，并设置宽限期。
- 丢包异常：为新任务和新服务器启用，并设置统计窗口、丢包阈值、最少样本数和冷却时间。
- 延迟异常：为新任务和新服务器启用，并设置统计窗口、最少成功样本数、冷却时间、自适应偏离比例和基线学习参数。
- 流量定时报告：为新服务器启用，并选择日报、周报、月报及报告内容。

默认配置只作用于之后新加入的服务器，不会改写已经存在的规则。

两类告警都依赖任务关联：新服务器只有被分配到延迟监测任务后，才会按当时保存的默认配置生成对应的“服务器 + Ping 任务”规则。修改默认值不会重写已有规则。

## 负载通知

### 默认开启

开启后，之后新加入的服务器会自动纳入该规则。已经存在的服务器不会因为这个开关被追加或移除。需要让旧服务器也使用同一规则时，仍应在规则中手动选择。

### 当前告警与静默

“当前告警”只列出正在触发的负载告警，可按告警规则和服务器搜索。

如果某台服务器的持续告警暂时无法处理，可只对该服务器设置静默：

| 选项 | 效果 |
| --- | --- |
| 静默 24 小时 / 3 天 / 7 天 | 到期后自动恢复通知 |
| 永久静默 | 需要手动解除 |
| 解除静默 | 立即恢复该规则下该服务器的通知 |

静默范围是“一条规则 + 一台服务器”。同一规则下的其他服务器不受影响。

静默只暂停通知渠道消息。告警检测继续运行，当前告警、仪表盘、实时负载和监控图表仍会显示真实状态。

## 延迟监测告警

告警按“服务器 + 延迟监测任务”保存。从任务中移除服务器后，该组合下的告警规则会被删除；重新加入任务后，如果启用了默认配置，会按当时保存的默认值新建，而不是恢复旧规则。

页面分为“丢包异常”和“延迟异常”两个页签，并可按任务或服务器查看。每条规则都可以单独新增、编辑、删除，也可以批量配置；列表中的“当前状态”只代表当前这条规则，不能把同一服务器的其他任务合并判断。

### 丢包异常

丢包规则使用最近统计窗口计算丢包率。只有实际样本数达到“最少样本数”且丢包率超过阈值时才进入异常；首次异常、持续异常和恢复会按冷却时间发送通知。统计窗口可设为 1 分钟至 24 小时，冷却时间可设为 1 分钟至 7 天，最少样本数为 1 至 100000，阈值大于 0% 且不超过 100%。

### 延迟异常

延迟规则独立于丢包规则，使用成功样本的平均时延判断“延迟过高”或“延迟过低”。统计窗口可设为 1 分钟至 24 小时，最少成功样本数为 1 至 100000，冷却时间可设为 1 分钟至 7 天。异常期间会按冷却时间重复提醒；恢复需要整个统计窗口的成功样本都回到正常范围。

固定基线模式需要填写基线、延迟下限和延迟上限。平均时延小于等于下限会判为延迟过低，大于等于上限会判为延迟过高；下限必须低于基线，基线必须低于上限。

自适应基线模式会从历史成功样本建立基线。可配置相对基线的下浮比例、上浮比例、基线学习窗口和建立基线所需的最少样本数；学习窗口为 1 小时至 30 天，且不能短于延迟告警统计窗口。基线建立前显示“基线学习中”，不会触发延迟告警；建立后显示“已就绪”。进入延迟告警后基线会显示“告警中已冻结”，避免异常样本污染基线；恢复后先进入“恢复等待”，完整恢复窗口通过后才继续学习。

修改会影响告警身份和当前状态。新增、编辑、删除规则以及保存两组默认配置，都会写入后台“操作记录”，便于确认是谁在什么时候调整了告警边界。

## 流量定时报告

报告周期、内容和推送时间仍按北京时间计算，口径见 [流量与报告](/admin/traffic)。

默认配置只决定新服务器是否启用日报、周报、月报，以及是否包含上行/下行流量和计费流量。已有服务器的报告开关不会被改写。
