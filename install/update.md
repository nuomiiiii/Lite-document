# 更新与数据库迁移

`2.3.0` 可以从 Lite 2.2.x、旧 Komari Lite 以及已支持的上游数据库来源升级。较旧版本仍可能触发 `2.1.12` 引入的监控数据格式迁移；从上游 `1.4.x` 迁入时会走与 `1.3.1` 相同的 V4 指标迁移。升级前后都应以页面显示的迁移状态为准，不要只看容器是否已经启动。

## 2.3.0 升级说明

- 产品、服务端二进制、Docker 镜像、Linux 安装目录和服务名统一为 Lite。升级时沿用站点设置、账号、节点、主题、数据和原监听端口。
- 管理后台切换到 MUI 视觉体系；登录、侧栏、服务器列表、独立服务器详情、设置和安装/升级引导使用统一布局。
- 新增账单中心。现有服务器的价格、货币、周期和到期时间会生成初始资费版本；账目采用追加和冲销记录，不回写历史金额。
- 新安装默认提供 Lite-Theme；从 Nezha 或旧默认主题升级时迁移到 Lite-Theme。原经典主题仍可按需单独安装 [lite-Classic](https://github.com/nuomiiiii/lite-Classic)。
- 配套 Agent 改为独立仓库的 Lite-agent `2.3.0.0`。新安装使用 `/opt/lite-agent`、`lite-agent` 服务和 `Lite-agent` 进程；旧节点可继续上报，再择机重新执行部署命令完成迁移。
- 首次安装改为五步引导；完整备份恢复只在欢迎页提供，进入后续步骤后不显示恢复入口。
- “新增服务器自动排序”默认关闭，开启后只影响之后首次识别国家/地区的新节点，不会修改已有排序。
- 离线通知、延迟监测告警和流量定时报告的新服务器默认配置不会改写已有服务器规则。
- 负载通知支持当前告警视图和按服务器静默；主题配置支持节点选择器和 Ping 任务选择器。
- 主题管理必须至少保留一个可用主题，不能把公开大屏主题全部删除。
- 已有节点的流量统计方式保持原值；“总和”只作为新节点首次编辑时的默认选择。
- 已保存的历史图表 `300s` 刷新配置会按 `120s` 处理，实时概览和历史图表的新默认值均为 `30s`。
- 启动清理不会再删除 `memory.total`、`swap.total`、`temperature` 和 `disk.total` 等仍在使用的系统指标定义及历史数据。
- Linux 直装在启用内置 HTTPS 后，在线更新不再因本机证书名称校验失败。安装或升级失败会回滚，避免留下不完整安装状态。
- 后台备份恢复、首次安装恢复和主题上传改为分段传输；网络中断后只需重试失败部分。

## 升级前

1. 停止会修改数据的旧实例。
2. 备份程序和完整 `data` 目录。
3. 记录当前版本和七位构建码。
4. 确认磁盘有足够空间容纳旧库、迁移临时数据和 WAL。

## Docker 更新

```bash
docker pull ghcr.io/nuomiiiii/lite:latest
docker rm -f lite
```

使用完全相同的 `data` 挂载重新创建容器。首次打开后台时，如出现迁移页面，请等待明确显示完成。

固定版本示例：

```bash
docker pull ghcr.io/nuomiiiii/lite:2.3.0
```

镜像包含 `linux/amd64` 和 `linux/arm64`。

## 支持的来源

当前迁移路径覆盖：

- 已验证的上游 `1.3.1`、`1.3.2` 数据库来源。
- 上游 `1.4.x` 指标数据库可与 `1.3.1` 走同一套迁移。
- 本分支 `2.1.7` 至当前正式版。
- 已经使用早期快照数据库格式的测试实例。

这里的“覆盖”只表示这些来源的数据迁移已适配，不表示 Lite 与上游的数据库结构、镜像或后台行为完全相同，也不自动包含未列出的上游版本。

如果同一份数据库同时包含两套完整的上游指标布局，迁移会拒绝继续，避免误选源表。指标迁移在 SQLite 事务中完成，失败会自动回滚且不残留临时表。

升级会保留原有数据保留天数，并固定启用分层降采样；旧版低资源模式会停用。

## 迁移过程中会发生什么

- 页面显示当前阶段、进度和错误。
- 指标、延迟和丢包记录转换为新的无损紧凑格式。
- 旧数据每批成功后才清理；单批失败会回滚并保留原数据。
- 已删除服务器或探测任务的历史残留会被清理。
- SQLite 释放出的空闲页会优先复用，不一定立刻反映为文件变小。

::: danger 不要中断正在写入的迁移
不要同时启动两个 Lite 实例指向同一个 `data` 目录，也不要在迁移进行中手动替换数据库文件。
:::

## 升级后检查

- 服务器在线状态和探测任务是否齐全。
- 历史曲线是否覆盖原有保留周期。
- 日报、周报、月报和计费流量口径是否符合设置。
- 数据库页面是否仍有迁移错误或待处理项目。
- 远程终端和文件管理能否通过当前反向代理建立连接。
- 公开大屏是否存在并启用了至少一个主题，服务器详情和网络排行跳转是否符合当前主题路由。
- 刷新页面或从公开大屏返回后，仪表盘是否先恢复上一帧并在后台静默更新。
- 负载通知、离线通知和延迟监测告警是否仍按预期触发；新加入的服务器是否套用了已保存的默认配置。
- Agent 是否为 Lite-agent `2.3.0.0` 或更新的兼容版本，服务日志是否显示连接成功，面板最后上报时间是否持续更新。

如果希望立即把 SQLite 空闲页归还给磁盘，可在业务低峰期执行“回收空间”。这不是日常必做操作。
