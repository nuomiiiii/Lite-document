# 数据库与空间维护

Lite 默认使用两类 SQLite 数据：主数据库保存账号、服务器、任务和设置；监控数据库保存指标、延迟和丢包记录。Lite `2.3.10` 当前构建继续调整 SQLite 缓存与进程内存管理，并改进多节点指标写入和探测结果落盘。升级自动备份使用当前连接生成独立快照，避免直接读取主库、WAL 或 SHM；这只适用于升级备份，不代表任意运行中的数据库文件都可以直接复制。

监控数据库也支持 MySQL、MariaDB 和 PostgreSQL，可在“系统设置 → 数据与存储 → 监控数据”填写连接串。连接示例、Docker 配置及已有历史的搬运方法见[外部监控数据库](/data/external-database)。主数据库当前仅支持 SQLite，本页的 WAL 和回收空间说明适用于本地 SQLite 文件。

## 文件组成

SQLite 运行时通常包含：

- `*.db`：主数据库文件。
- `*-wal`：已经提交但尚未检查点回主文件的页。
- `*-shm`：WAL 协调共享内存文件。

页面中的“总占用”应包含数据库文件、WAL 和 SHM。只看 `.db` 文件会漏掉运行时占用。

## 为什么主库会变大

WAL 检查点把数据页写回 `.db` 后，主文件变大、WAL 变小是正常现象，总占用才是应观察的指标。网页上 WAL 保持不变也不能证明没有写入主库。

SQLite 删除记录后会形成可复用空闲页，文件不会自动按删除量缩小。后续写入会优先复用这些页。

## 数据保留

监控数据会按设置的保留时间自动整理。较早的数据可能以较低时间精度显示，但仍可用于查看长期趋势。缩短 Agent 上报或探测间隔、增加任务和节点、延长保留时间，都会增加磁盘占用。

从其他版本迁入数据时，请按[更新与数据库迁移](/install/update)操作并等待迁移完成，不要手工修改数据库表。

### 节点管理数据清理 <PlusBadge /> {#节点管理数据清理}

Lite-Plus `0.2.0` 不再持续保存逐笔用量流水，并会清理旧记录；用户累计用量、额度和套餐记录继续保留。

已完成、失败或被新配置替代的下发命令会清除配置载荷，相关历史命令记录保留 7 天后清理。待执行命令继续保留，不受此项历史清理影响。

自动清理后 SQLite 文件仍可能保留可复用空闲页。需要降低磁盘占用时，再使用本页的“回收空间”。

## WAL 维护

WAL 截断失败不会删除尚未安全落盘的数据。系统会保留 WAL 并在后续条件合适时重试。页面显示的“预计下次截断”应随真实执行结果更新。

如果日志持续出现 `context deadline exceeded`，应同时检查：

- CPU 和磁盘是否长期饱和。
- 是否有大量 1 秒或 5 秒探测任务。
- 是否正在执行迁移、回收空间或长周期查询。
- 容器卷是否位于性能较差的网络盘。

## 回收空间

“回收空间”会整理 SQLite 文件并尝试把空闲页归还给磁盘。它适合以下情况：

- 刚完成大版本迁移或大量历史数据清理。
- 已经确认业务低峰且磁盘有临时工作空间。
- 需要立即释放空间，而不是等待后续数据复用空闲页。

不要把回收空间设为高频定时任务。数据库繁忙时等待或失败并不意味着数据损坏。
