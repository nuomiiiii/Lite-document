# 备份、导入与迁移

备份入口位于“系统设置 → 站点”。不要只备份一个看起来最大的数据库文件。

## 完整备份

完整备份用于灾难恢复或迁移整个实例，包含：

- 站点、账号、服务器和任务配置。
- 主数据库与监控数据库。
- 历史监测、延迟、丢包和流量账本。
- 当前版本支持的主题与相关配置。

完整备份可能包含 Agent Token、登录配置和其他敏感信息，应通过可信连接下载并加密保存。

后台下载或恢复完整备份、首次安装恢复以及主题上传会对大文件使用分段传输。进度显示真实字节和百分比，稳定到达 100% 后再进入服务端处理。网络中断后只需重试失败部分，不需要整包重传。取消上传后不会继续合并未完成的分段。

## 仅导出配置

<div class="version-note"><strong>2.1.12</strong><span>仅导出配置已纳入 2.1.12 正式版，可在不携带历史监测数据时切换分支或重建实例。</span></div>

配置包保留服务器、探测任务和必要设置，不包含历史指标、延迟、丢包和流量账本。它适合：

- 从本分支迁往兼容的上游版本。
- 从上游最新版本迁入本分支。
- 复制节点和任务结构到新实例。

这里的“兼容”仅指配置包中目标版本明确支持的字段，不表示完整备份、数据库文件或运行行为完全一致。是否能跨版本导入仍取决于目标版本支持的字段。导入页面会显示校验结果和错误，不应静默丢弃无法识别的关键配置。

## 导入前检查

1. 确认备份来自可信来源。
2. 记录当前版本与目标版本。
3. 先对当前实例做完整备份。
4. 保证磁盘空间能容纳现有数据和导入临时文件。
5. 导入期间不要启动第二个实例读写同一个目录。

## 导入后检查

- 服务器数量、分组和 Token 是否符合预期。
- 探测任务数量、地址、协议和间隔是否一致。
- 流量限额、重置日、价格和通知设置是否保留。
- 历史曲线与报告是否符合所选备份类型。
- 主题是否存在且已经启用。

## 直接备份 data 目录

这是最稳妥的冷备份方式：停止 Komari Lite 后复制完整 `data` 目录。运行中只复制 `.db` 而漏掉 `-wal` 文件，可能得到时间点不一致的备份。
