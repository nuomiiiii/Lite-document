手册由 Lite 与 Lite-Plus 共用，以上为 Lite 的版本基线。带 <PlusBadge /> 徽标的页面、段落或表格行仅适用于 Lite-Plus；其他共用功能沿用原章节，部署命令与默认端口按各自项目选择。

同一版本号可能包含不同构建，具体标识以“关于”页面和对应项目 GitHub Release 中的七位构建码为准；排查问题时应同时提供项目名称、版本号和构建码。

使用 Snapshot 时，应以对应 Release 的测试说明为补充，并在更新前备份完整 `data` 目录。

Plus 章节按当前项目代码编写，安装与更新使用 Plus 自己的仓库和产物。主要内容包括：

- [部署与从 Lite 升级](/plus/install)：独立脚本、镜像和 Agent，说明新安装默认端口以及保留原入口的升级步骤。
- [入站与协议](/plus/inbounds)、[出站与路由](/plus/forwarding)：管理代理入口、传输安全、分享地址、额外出口与分流规则，并检查节点下发结果。
- [用户与套餐](/plus/users)：分配入站、流量额度、期限、单节点限速与在线 IP 上限，说明套餐修改和续费的影响。
- [节点证书](/plus/certificates)：主控申请证书或绑定节点已有证书文件，与面板 HTTPS 分开管理。
- [订阅与外部链接](/plus/subscriptions)：通过“订阅信息”“入口管理”和“模板管理”管理订阅，独立端口可复用内置 HTTPS；支持客户端自动识别、专用链接与二维码，并合并外部分享链接与订阅。
- [订阅模板](/plus/templates)：导入 Clash / Mihomo、Loon、Surge 和 sing-box 配置，设置系统默认及套餐、用户专属模板，按授权节点生成完整配置并预览。
- [节点管理接口](/plus/api)：补充 `admin:nodemgt.*` 方法、字段单位、认证与 Plus Agent 扩展。

第一次使用请从 [Lite-Plus 功能与使用流程](/plus/)开始。普通 Lite 不提供这些节点管理功能，普通 Lite-agent 也不能代替 Plus Agent 执行节点配置。

## Lite 2.3.9、Agent 2.3.6.3 与 Theme 1.2.9 重点变化

- [主题更新](/themes/#更新主题)：支持一键检查并更新所有已安装主题，也可开启服务端自动更新。自动更新默认关闭、间隔默认 24 小时，可设为 1–720 整数小时；无来源主题跳过，同版本无需重复安装。
- [监测与回程](/admin/monitoring#延迟与丢包的显示口径)：配套 Agent 上报小数毫秒，延迟保留两位小数；统计只计算成功样本，降采样均值按成功样本数加权。全部失败时不返回延迟值，主题曲线显示断点，丢包仍正常统计。

- [定时任务](/remote/schedules)：新增“远程管理 → 定时任务”，支持按间隔、每天、每周和每月执行命令，每周可选多个星期；日历定时按北京时间计算。支持立即执行、启用与停用、任务排序，以及各节点输出和退出码查询。保存后无需保持浏览器打开，关闭远程管理或相关账号安全变更会停用任务。
- [账号与安全](/security/account)：保留通行密钥、头像、全局自动登出时长和登录会话管理；头像也可通过公开主题接口按登录状态返回。
- [服务器管理](/admin/servers)：账单到期时间支持 IANA 时区、本地日期和时分秒；列表、公开主题和大屏按到期瞬间向上取整显示剩余天数。自动续费按服务商当地时区推进，处理夏令时跳时，并避免并发编辑覆盖较新的到期时间。
- [成本中心](/admin/billing)：费用概览显示到期当地时间和估算剩余价值；删除节点后不再计入当前汇总，历史账目仍保留。汇率、原始币种和地区覆盖值继续按资费版本保存。
- [通知与告警](/admin/notifications)：支持统一渠道或按事件分配多个渠道，并可在 1–3600 秒内汇总相同内容的告警。新增“告警中心”，集中查看离线、负载、延迟/丢包和回程线路告警，可搜索、筛选并设置 24 小时、3 天、7 天或永久静默；静默只暂停异常通知，恢复通知仍按规则发送，检测和列表展示继续。
- [仪表盘](/admin/dashboard)：新增“仪表盘时区”设置，默认 `Asia/Shanghai`，今日流量、按日趋势和今日恢复按所选 IANA 时区切日；同时保留续费日历、告警概览与按服务器和 Ping 任务定位的时延、抖动、丢包排行。
- [MCP 代理与 AI 授权](/remote/mcp)：临时授权最长可调至 72 小时，默认最长仍为 24 小时；新增默认不勾选的长期授权，退出登录和正常重启后保留，仍支持撤销。活动授权支持编辑服务器范围、用途备注和有效期；可授权当前及未来符合条件的所有服务器，修改范围或有效期会中断该授权正在运行的操作。
- [API 与 RPC2](/development/api)：补充告警中心、仪表盘时区、MCP 活动授权编辑、主题更新及探测统计的参数与返回字段。公共接口继续提供到期时区、剩余价值和登录头像；全部探测失败时省略延迟字段。API Key 不能签发或使用远程授权，也不能访问备份、主题、账号和节点 Token 等敏感操作。
- [Agent 安装与维护](/install/agent)：当前配套 Lite-agent `2.3.6.3`，支持 ICMP、TCP 和 HTTP 探测的小数毫秒上报，兼容旧版 Lite 的整数毫秒字段。远程文件二进制传输与并行上传、上游迁移、精确流量重置、HTTP 压缩回退及 Windows 安装修复继续保留。
- [备份与空间维护](/data/backup)：完整备份和配置备份继续包含头像，Passkey 数据随主数据库保存；升级自动备份改用 SQLite 连接内的 `VACUUM INTO` 独立快照，保护升级过程中的锁状态；删除历史记录后如需立即降低主数据库占用，应使用“回收空间”。
- [反向代理与 Tunnel](/security/reverse-proxy)：Docker 镜像不内置 `cloudflared`，后台 Tunnel 管理需要挂载主机二进制并设置 `LITE_CLOUDFLARED_BIN`，或单独运行 cloudflared 容器。
- [主题管理](/themes/)：配套 Lite-Theme 为 `1.2.9`，公开大屏与后台统一 UI 风格，调整首页卡片、详情和图表，并支持 Swap 资源趋势。系统设置新增 GitHub 代理，可用于主题更新、导入和市场下载；各节点首页探测任务、手机端概览、卡片剩余价值和登录后管理员头像继续保留。

## 从旧版本沿用的行为

- [外部监控数据库](/data/external-database)：支持 MySQL、MariaDB 和 PostgreSQL，在“数据与存储 → 监控数据”填写连接串即可切换，已有历史可在“迁移与维护”中搬运。主数据库继续使用本地 SQLite。

- 自动发现新节点的接口和后台入口已经下线；新安装及 Docker 重建都使用后台为具体节点生成的普通部署命令。
- 远程终端、文件管理、远程执行和定时任务统一受站点开关、Agent 本地开关及重新验证保护。浏览器短期授权绑定当前管理员登录会话；终端与文件管理共用授权范围，远程执行及定时任务的管理操作使用 `exec` 范围。已保存并启用的定时任务由服务端继续调度，不依赖浏览器会话。
- 主题上传、更新、GitHub 安装和市场安装统一限制为 128 MiB，并加强网络下载地址检查。
- 完整备份会携带恢复加密两步验证数据所需的实例密钥，恢复前会校验数据库与密钥是否匹配。
- 管理员密码改用 Argon2id，旧密码会在成功登录后自动升级；2FA Secret 加密保存，并阻止同一验证码重复使用。
- 主题常用的 `common:getNodes` 不再返回 Agent 版本、部署状态和远程管理状态等后台字段。
- 远程执行可避免同一任务因重复投递而再次运行，并能在 Agent 异常退出后报告未知执行状态；旧自动发现安装只读取已有身份文件，不再注册新节点。

## 与上游的关系

Lite 基于 [komari-monitor/komari](https://github.com/komari-monitor/komari) 持续开发，但数据库结构、后台界面、Agent 更新源和部分公共接口兼容逻辑已经不同。

本手册统一使用以下口径：

- “与上游一致”表示当前 Lite 已按实际实现核对，所述行为可按同一方式使用。
- “上游兼容”只表示文中明确列出的版本、数据或接口可以迁移或调用，不代表镜像、数据库和后台实现完全相同。
- “Lite-agent”表示 `nuomiiiii/Lite-agent` 独立仓库的配套 Agent。当前只支持协议 2，不代表兼容上游或旧版 Agent。
- <PlusBadge /> 表示 Lite-Plus 专属内容；“Lite-Plus-agent”使用 Plus 独立的仓库、程序和更新源。
- “本项目官方脚本”表示 `nuomiiiii/lite` 仓库发布的安装脚本，不是上游仓库的脚本。
- Lite 与上游确有差异时，页面会直接标注差异和适用范围，不要求读者自行判断。

不要混用两个项目的 Docker 镜像地址，也不要让两个项目同时读写同一份数据目录。从上游切换到 Lite 前必须备份；当前已适配的迁移来源见[更新与数据库迁移](/install/update)。第三方主题和外部集成应使用公共接口，不应直接依赖内部数据库结构。
