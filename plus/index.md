# Lite-Plus 功能与使用流程 <PlusBadge />

Lite-Plus 在 Lite 的监控、告警、账单、远程管理和 MCP 功能基础上，新增代理节点管理与服务器防火墙。管理员可在后台配置入站、出站、路由、节点用户、套餐、证书和订阅，由 Lite-Plus-agent 在目标服务器上应用。

本手册由 Lite 与 Lite-Plus 共用。带 <PlusBadge /> 的页面或段落仅适用于 Lite-Plus；共用功能继续查阅原有章节。Plus 使用独立的服务端、管理后台和 Agent 更新源，不能把 Lite 的安装命令、镜像或版本号直接当作 Plus 使用。

## 当前项目基线

| 组件 | 版本 | 用途 |
| --- | --- | --- |
| Lite-Plus | `0.1.2` | 服务端、节点管理后台与服务器防火墙 |
| Lite-Plus-agent | `0.0.2.4` | 监控采集、同进程 Xray / sing-box 节点管理与防火墙下发 |
| Lite-Theme | `1.2.9` | 共用公开主题 |

以下说明按当前项目代码编写。实际安装产物和构建码以对应项目 Release 及后台“关于”页面为准。

服务器防火墙位于“远程管理 → 防火墙”，支持按节点维护 IPv4 / IPv6 规则、禁止 ping、入站默认拒绝和 SSH 端口，见[服务器防火墙](/plus/firewall)。

## 第一次配置

1. 按[部署与从 Lite 升级](/plus/install)安装 Plus 服务端。
2. 在“服务器”添加或打开已有节点，使用该节点生成的 Plus 部署指令安装 Lite-Plus-agent，确认节点在线。
3. 使用 TLS 时，先在“节点管理 → 证书”配置证书。多个节点使用同一域名下的子域名时，可在“签发管理”申请根证书，再在“证书配置”中按节点下发；也可使用单节点主控申请或已有文件。Reality 使用自己的密钥配置。
4. 在“节点管理 → 入站”创建入口，配置监听端口和客户端可达的分享地址。需要由 Plus 放行主机端口时勾选“同时放行该端口”，并按[防火墙使用前提](/plus/firewall#使用前提)开启远程控制。
5. 按需创建套餐，再在“用户”创建节点用户，至少授权一个入站。
6. 在“概览”或列表的“下发”列确认节点返回“已生效”。
7. 打开“订阅 → 入口管理”，手动填写客户端实际可达的对外地址并保存，再到“订阅信息”复制用户订阅地址或预览二维码。设置非零监听端口后，订阅只通过该独立端口提供，反向代理也需回源到订阅端口；可复用面板内置 HTTPS 证书，复用开关不会自动填写证书域名。
8. 需要完整 DNS、分组和路由规则时，在“订阅 → 模板管理”保存并应用模板；开启客户端自动识别或选择客户端专用链接，再导入客户端。

节点用户由管理员创建和管理，是代理连接身份；不会获得面板登录、远程终端或 MCP 管理权限。

## 列表显示与列宽

电脑端可拖动表头列边界调整入站、出站、路由、用户、套餐、订阅、证书及审计等列表的列宽。需要恢复默认布局时，点击操作列表头的“重置列宽”。

每个列表分别记住当前浏览器中的列宽，更换浏览器或设备后需要重新设置。长名称会截断显示，可悬停查看完整内容；用户的多个入站、在线 IP 等内容可按列表入口展开查看。

## 保存与节点生效

保存配置后，主控会持久保存待下发内容，通过 Agent 连接发送并等待结果。节点离线时，配置会等待节点恢复连接。

| 显示状态 | 含义与处理 |
| --- | --- |
| 尚未下发 | 尚无可用于判断的下发记录；保存需要应用的配置后再查看 |
| 已保存 | 主控已保存，等待节点上线或发送 |
| 已发送 | 已向节点投递，等待应用结果 |
| 已生效 | 节点已确认应用成功，可继续用客户端验证连接 |
| 应用失败 | 查看错误信息，修正端口、证书或协议配置后重新保存 |

“已保存”不代表服务器已经开始监听；“已签发”也不等同于入站已经应用证书。排查时同时核对节点在线状态、证书状态和下发结果。

勾选入站防火墙联动时，还需在“远程管理 → 防火墙”确认规则已应用；节点管理配置与防火墙分别返回结果。

修改监听、协议或用户配置可能让相关连接重新建立。需要确认实际行为时，先保存并等待“已生效”，再从客户端重新连接。
