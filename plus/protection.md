# 服务防护 <PlusBadge />

入口位于“远程管理 → 防火墙 → 服务防护”。选择服务器后，可配置 TCP 连接保护、Web / SSH 日志检测、动态封禁、联动组和白名单。

访问放行条件仍在“规则”页签维护；服务防护用于处理已放行服务的异常行为。

## 使用前提与范围

- 使用当前 Lite-Plus `0.2.0` 与 Lite-Plus-agent `0.2.0.0` 的配套构建，并开启站点远程管理和目标 Agent 的远程控制。页面提示升级 Agent 时，先更新再检查。
- 节点需要 Linux、nftables 及相应内核能力。Agent 通常以 root 运行，也可按环境授予所需权限；实际支持情况以“检查环境”的结果为准。
- 安装、保存、日志预览和解除封禁等操作会要求远程操作身份验证；API Key 不能调用服务防护接口。

防护覆盖主机入站（INPUT）。经 Docker / 桥接 DNAT 转发的 FORWARD 流量不在覆盖范围内，不能用这项功能代替容器内部或云平台的访问控制。

## 一、检查并启用环境 {#environment}

1. 选择目标服务器，进入“服务防护”，点击“检查环境”。
2. 点击“预检查”，查看当前防火墙、防护引擎、执行计划和需要处理的问题。
3. 页面提供“安装更新并启用”时，点击并完成身份验证。Agent 会按需安装或更新发行版的 nftables，并启用 Plus 独立防护表。
4. 等待显示“nft 防护已就绪”，再开启“启用服务防护”，添加需要保护的服务。

启用防护会保留原静态防火墙后端和已有规则。缺少权限、软件包或内核能力时，按检查详情处理后重新运行预检查；安装成功仍需等待防护验证通过。

## 二、新建服务防护

在“防护列表”点击“新建防护”。也可从“规则”页签中已启用、放行单个端口的规则点击“配置防护”，预填该服务的信息。

配置分为“服务信息”“检测与日志”“处置与联动”三部分：

<div class="plus-settings-table">

| 配置项 | 填写方式 |
| --- | --- |
| 服务名称 | 填写方便识别的用途，如网站 HTTPS 或 SSH |
| 协议与目标端口 | 填写实际服务协议及单个端口；TCP/UDP 会分别保存两条防护 |
| 本地地址 | 可选，填写节点上的监听 IP；留空匹配主机对应端口 |
| TCP 连接保护 | 无需访问日志，可设置 SYN 速率、SYN burst 和并发连接上限 |
| 日志行为检测 | 选择已接入的日志来源，或按来源的协议、端口和本地地址自动匹配 |
| 模式 | 新建默认“观察”；核对命中情况后可改为“执行” |
| 封禁时长 | 日志检测执行封禁时使用，默认 600 秒；勾选“永久”后持续到解除 |
| 联动组 | 默认仅当前节点；日志检测可选择当前节点已加入且启用的联动组 |
| 启用此服务防护 | 关闭后保留该服务配置，暂停此项防护 |

</div>

SYN 速率、并发连接上限及日志检测阈值填 `0` 表示关闭对应检测。按正常业务量设置阈值，先用观察模式确认是否会命中正常访问，再切换执行。

### TCP 连接保护参数

这些限制针对当前服务，按来源 IP 分别计算。SYN 是发起 TCP 连接时发送的请求包，可以理解为客户端向服务器“申请建立连接”。

<div class="plus-settings-table">

| 参数 | 通俗说明 |
| --- | --- |
| SYN 速率 | 限制同一 IP 发起连接请求的速度。例如填 `20`，表示持续请求按每秒 20 个 SYN 包控制 |
| SYN burst | 短时突发容量，允许客户端在很短时间内集中发起一些连接请求；突发过后仍受 SYN 速率限制。例如填 `40`，表示突发容量为 40 个包 |
| 并发连接上限 | 限制同一 IP 同时占用的 TCP 连接数。例如填 `100`，表示并发连接上限为 100 条，用于限制同时维持大量连接的情况 |

</div>

SYN burst 需配合 SYN 速率使用；填 `0` 时，突发容量默认与 SYN 速率相同。共享同一公网 IP 的多个用户会合并计数，填写时应考虑实际访问量。

### 连接保护与日志封禁的区别

<div class="plus-settings-table">

| 检测方式 | 观察模式 | 执行模式 |
| --- | --- | --- |
| TCP 连接保护 | 记录网络观察命中，保持业务通行 | 超限连接直接丢弃，不加入 IP 封禁名单 |
| 日志行为检测 | 记录请求、路径或 SSH 失败命中 | 按来源 IP 动态封禁，可同步到联动组 |

</div>

动态封禁会拦截该 IP 的全部入站连接，包括已建立连接，并非只拦截触发检测的服务端口；本机主动发起连接的回包继续放行。UDP 暂不提供上述连接和 Web 日志检测，但来源 IP 被封禁后，其入站 UDP 也会被拦截。

## 三、接入日志来源

日志接入是可选项，TCP 连接保护可以独立使用。Agent 读取服务器已有日志，不会替你修改 Caddy、Nginx 或 SSH 的日志配置。

在“日志来源”选择对应格式，填写日志路径、绑定服务等信息，点击“预览字段”确认能解析，再保存来源。随后回到防护列表，在“日志行为检测”中选择该来源并设置阈值。

<div class="plus-settings-table">

| 字段 | 填写方式 |
| --- | --- |
| 日志格式 | Caddy JSON、Nginx combined、Nginx JSON 或 SSH 失败日志，需与实际内容一致 |
| 日志绝对路径 | 填写 Agent 所在主机可读取的完整路径，如 `/var/log/nginx/access.log` |
| 部署方式 | 直接接收客户端连接选“直连”；经过 CDN 或外部反向代理选“代理后（仅观察）” |
| 绑定协议、端口 | 填写日志对应服务的实际协议与端口；Nginx combined 必须绑定协议及单个端口 |
| 本地地址 | 可选，限定该日志来源对应的节点 IP |
| 站点过滤 | 可选，仅处理指定站点的日志 |

</div>

限定本地地址的日志防护需要明确选择来源。来源也应绑定同一地址，或使用包含目标地址的 Nginx JSON 日志。

代理后的真实客户端 IP 通常不能由本机 nftables 直接拦截，因此这类来源只参与观察。将来源改为“代理后”并保存时，关联防护也会调整为观察模式。

### Web 请求与敏感路径

“单源请求阈值”按来源 IP 统计窗口内请求条数。“敏感路径”则只统计命中已填写路径的记录，路径每行一项，可分别设置计数窗口和命中条数。

路径不以 `/` 结尾时精确匹配；以 `/` 结尾时匹配该目录及其下路径。例如 `/.env` 匹配该文件，`/.git/` 匹配该目录及子路径。阈值按实际业务设置，不要把正常登录页或常用接口直接当作异常路径。

### SSH 密码失败检测

1. 在“日志来源”选择“SSH 失败日志”。
2. 按主机实际日志填写 `/var/log/auth.log`、`/var/log/secure` 或 `journal:sshd`，绑定端口填写当前 SSH 端口。
3. 新建 TCP 服务防护，目标端口与来源的 SSH 端口保持一致，选择该 SSH 来源。
4. 设置“SSH 密码失败阈值”，例如在 60 秒窗口内失败 3 次；先观察，再按需要切换执行。

同一节点只能接入一条 SSH 来源。不要同时添加 journal 和文件日志，以免一次失败被重复计算。更改 SSH 端口后，同步调整日志来源与服务防护中的端口。

## 四、白名单与联动组

### 白名单

在“白名单”添加无需参与防护检测和拦截的来源 IP。每项填写一个 IPv4 或 IPv6 地址，不使用 CIDR 网段。

白名单针对当前节点生效。共享 NAT 出口的多个用户会共用同一个来源 IP，设置请求或连接阈值时应一起考虑；管理出口和可信监测地址可按需加入白名单。

### 联动封禁

1. 先在各节点完成防护环境启用。
2. 在“联动组”新建组，并分别在需要加入的节点点击“加入”。
3. 编辑服务防护，在“处置与联动”中选择该组，再保存。
4. 日志检测触发封禁后，同组节点同步该来源 IP 的封禁；展开成员可查看各节点的下发状态。

TCP 连接超限只处理超限连接，不产生供联动组同步的 IP 封禁。更换联动成员后，也应查看各成员是否已应用。

## 五、查看记录与解除 {#records}

“动态封禁”中集中显示封禁与观察记录，可搜索 IP、原因、服务或来源节点，并筛选封禁中、仅观察、已到期和已解除。

- **本机解除**：解除当前节点的本地封禁。
- **组内解除**：向该记录所属联动组同步解除该 IP。
- **自动到期**：有限时长封禁到期后失效；永久封禁需要手动解除。

解除后新的违规行为仍可再次触发封禁。需要持续免于防护时，在相应节点维护白名单。

“日志来源”还会显示解析数量、错误、读取延迟和最近读取时间。没有命中记录时，先检查是否有新日志、路径与格式是否正确、来源绑定是否与服务一致，再核对阈值和运行状态。

保存配置后确认下发结果为“已应用到节点”。节点离线时配置等待重新连接；仅看到保存成功，不代表目标主机已经启用防护。

开发接入见[服务防护接口](/plus/protection-api)。
