# 订阅与外部链接 <PlusBadge />

本页仅适用于 Lite-Plus。每个节点用户自动生成一条订阅，可从“节点管理 → 订阅”管理，也可在用户列表点击“预览订阅”。

订阅页面分为三个页签：

<div class="plus-settings-table">

| 页签 | 用途 |
| --- | --- |
| 订阅信息 | 查看用户订阅，编辑默认格式、自动识别和启用状态，复制地址或预览二维码 |
| 入口管理 | 设置订阅监听端口、对外地址、URL 路径、HTTPS，以及名称与用量下发 |
| 模板管理 | 导入或编辑客户端配置，设置系统默认及套餐、用户专属模板，见[订阅模板](/plus/templates) |

</div>

## 配置订阅入口

切换到“入口管理”，填写监听端口、反代端口、URL 路径和对外地址后点击“保存”。“复用内置 HTTPS”位于下方独立卡片中，切换后会保存设置。

<div class="plus-settings-table">

| 设置 | 说明 |
| --- | --- |
| 监听端口 | 留空或 `0` 使用面板入口，保存的 `0` 在表单中显示为空；填 `1–65535` 的非零端口后，订阅只通过独立端口提供，默认 HTTP，开启“复用内置 HTTPS”后使用 HTTPS |
| 反代端口 | 对外映射端口，只影响复制出的地址；留空或 `0` 跟随监听端口，保存的 `0` 显示为空，不会自动创建反向代理 |
| URL 路径 | 例如 `/a1b2c3/`，首次自动生成随机前缀；保存后所有用户共用此前缀 |
| 对外地址 | 手动填写客户端可达的 IP 或订阅域名，建议包含实际协议，例如 `https://sub.example.com`；泛域名证书需填写实际订阅主机名 |
| 复用内置 HTTPS | 使用面板内置 HTTPS 的证书与私钥，让独立订阅端口提供 HTTPS；开启前需先在后台“反向代理”中配置内置 HTTPS 证书 |

</div>

复制的地址由填写的对外地址、端口、路径和用户 Token 组成。对外地址留空时只生成相对路径，不会自动采用面板地址或证书域名。切换“复用内置 HTTPS”不会覆盖已填写的对外地址；修改路径或对外入口后，应重新复制订阅地址并更新客户端。

**独立端口与面板入口隔离。** 设置非零监听端口后，直接访问面板 HTTP / HTTPS 端口上的订阅路径会返回 `404`，自定义面板端口也相同。订阅域名或同域名下的订阅路径必须反向代理到独立订阅端口；独立端口只提供订阅，不提供管理后台。监听端口留空或设为 `0` 时，订阅仍沿用面板入口。

订阅地址包含用户访问凭据，请仅交给对应用户使用，不要放入公开截图或页面。

### 下发订阅名称与用量

“入口管理”中还提供两个独立开关，默认都关闭，切换后自动保存：

<div class="plus-settings-table">

| 开关 | 客户端可显示的内容 |
| --- | --- |
| 下发订阅名称 | `用户名 · 套餐名`；没有当前有效套餐时仅使用用户名 |
| 下发流量和到期信息 | 用户已用流量、流量额度和到期时间；无限额时额度为 `0`，不过期时不下发到期时间 |

</div>

开启后让客户端更新订阅，是否显示取决于客户端支持情况。已导入的订阅可能保留用户手工修改的名称，需要时重新导入。这些开关不会修改订阅地址，代理节点名称仍使用各自的入站名称。

已用流量为 Plus 统计的上下行合计，包含的外部订阅节点用量不计入此值。外部节点的额度与期限仍由对应提供方管理。

### 复用内置 HTTPS

需要由主控直接提供 HTTPS 订阅时：

1. 在后台“反向代理”中配置面板内置 HTTPS 的证书和私钥路径，确认文件可读取且证书匹配，具体见[内置 HTTPS](/security/https)。
2. 返回“节点管理 → 订阅 → 入口管理”，设置非零监听端口，例如 `28999`。
3. 在“对外地址”手动填写实际订阅主机名，例如 `https://sub.example.com`。证书为 `*.example.com` 时，也应填写实际使用的 `sub.example.com`，不能直接把通配符作为访问地址。
4. 按实际对外映射填写反代端口，保存表单并开启下方“复用内置 HTTPS”，放行或映射订阅监听端口。无需在订阅页重复填写证书路径。
5. 回到“订阅信息”，重新复制订阅地址，确认域名解析、端口和证书均可正常访问。

例如，面板证书覆盖 `sub.example.com`，对外地址填写 `https://sub.example.com`，监听端口为 `28999`、反代端口留空、URL 路径为 `/a1b2c3/` 时，生成的地址为 `https://sub.example.com:28999/a1b2c3/<token>`。仅有 `*.example.com` 的证书不覆盖根域名 `example.com`，不要把对外地址误填为根域名。

复用的是**主控上的面板证书**。使用外部文件时，Docker 部署需挂载证书目录，并在面板 HTTPS 设置中填写容器内路径；也可在面板内置 HTTPS 中[复用根域名证书](/security/https#复用根域名证书)，由主控自动生成证书文件。[节点证书](/plus/certificates)中的 Agent 文件仍用于代理入站。更新面板 HTTPS 设置或重新加载面板证书时，也会尝试重载独立订阅服务，操作后应检查订阅地址能否正常访问。

关闭“复用内置 HTTPS”后，独立订阅端口使用 HTTP；需要对外 HTTPS 时，按下一节配置反向代理。监听端口为 `0` 时不启动独立服务，订阅沿用面板入口，其 HTTPS 按[内置 HTTPS](/security/https)或[反向代理](/security/reverse-proxy)配置。

### 独立订阅端口示例

通过反向代理提供 HTTPS 时，在“入口管理”中设置监听端口 `28999`、反代端口 `443`、URL 路径 `/a1b2c3/`、对外地址 `https://sub.example.com`，关闭“复用内置 HTTPS”并保存。`28999` 是本例自行设置的订阅监听端口，使用时替换为实际端口：

- 反向代理将该域名请求转发到主控的 `127.0.0.1:28999`，由反向代理提供 HTTPS。
- Docker 部署还需把容器的订阅端口映射给反向代理；本例同机反代可用 `127.0.0.1:28999:28999`，映射占用的宿主机端口不能与其他服务重复。
- 独立端口仅提供订阅。本例关闭了“复用内置 HTTPS”，主控订阅端口使用 HTTP，客户端的 HTTPS 由反向代理提供。

主控与反向代理在同一台主机、订阅使用独立域名时，可把该域名的全部路径转发到订阅端口。Nginx 示例：

```nginx
server {
    listen 443 ssl;
    server_name sub.example.com;
    ssl_certificate /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:28999;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_redirect off;
    }
}
```

把域名、证书路径与端口换成实际值。`proxy_pass` 不附加路径，保留客户端请求中的订阅前缀和 Token，例如 `/a1b2c3/<token>`。上例由当前 Nginx 提供 HTTPS，因此 `X-Forwarded-Proto $scheme` 的值为 `https`，也可在这个 HTTPS 配置段中固定写成 `https`。远端或容器化反代应改用它实际可达的主控地址。

订阅与管理后台共用一个域名时，可将上例的 `location /` 改为 `location /a1b2c3/`，只把订阅路径交给独立端口，其他请求继续转发到面板。订阅路径的 `proxy_pass` 仍需指向 `http://127.0.0.1:28999`，不能指向面板端口。两种方式都需要保留后台配置的 URL 路径，不能在转发时去掉前缀。

以上用于独立订阅服务。反代整个 Plus 管理后台时，使用[反向代理与 Tunnel](/security/reverse-proxy#nginx-示例)中的完整配置，保留 Agent、终端和实时状态所需的 WebSocket 转发头与长连接设置。

### 升级后订阅返回 404

1. 在“入口管理”确认监听端口。填了非零端口时，检查该端口是否已监听，Docker 是否已映射。
2. 检查反向代理回源是否仍指向面板端口，改为独立订阅端口，并保留完整 URL 路径和 Token。
3. 重新复制订阅地址，核对对外地址、协议和端口；使用 HTTPS 回源时，与“复用内置 HTTPS”的实际状态保持一致。
4. 仍返回 `404` 时，检查用户是否启用、是否到期、订阅是否启用，以及地址中的 Token 是否正确。

## 选择格式与预览

| 格式 | 用途 |
| --- | --- |
| `xray` / `base64` | Base64 编码的分享链接列表，用于兼容此类订阅的客户端 |
| `clash` | 原有 Clash / Mihomo 节点列表格式 |
| `sing-box` | 原有 sing-box JSON 节点配置 |

编辑订阅可设置默认格式、启用状态和“自动识别客户端”。开启自动识别后，主控根据客户端请求中的 User-Agent 选择输出；未识别到客户端时使用已保存的格式。旧订阅升级后仍保留固定格式，需要手动开启自动识别。

“预览订阅”可选择客户端、查看兼容性提示，复制该客户端专用的订阅地址，并查看或下载二维码。分享链接订阅还会解码展示节点及各自的二维码。需要查看、对照或下载完整配置时，切换到[模板管理](/plus/templates#预览、导出与删除)使用模板预览。

订阅列表默认遮住对外域名/IP，点击复制或预览图标操作，悬停可查看名称；复制图标仍复制完整链接，眼睛图标可临时显示。若提示“复制失败，请手动选择文本。”，选中显示的地址手动复制。

### 为指定客户端生成配置

在订阅地址追加 `?target=mihomo` 等参数，可固定选择客户端并使用其对应的[订阅模板](/plus/templates)：

| `target` | 输出 |
| --- | --- |
| `mihomo`、`clash`、`stash` | 对应客户端的完整 YAML 配置，使用 Clash 类型模板 |
| `loon` | Loon 配置，使用 Loon 类型模板 |
| `surge`、`surge-mac` | Surge iOS / macOS 配置，使用 Surge 类型模板 |
| `sing-box` | sing-box 完整 JSON 配置 |
| `v2ray` | Base64 分享链接订阅，不使用规则模板 |

例如 `/a1b2c3/<token>?target=mihomo`。参数只影响返回的配置，原有订阅路径和 Token 保持不变。

选择顺序为：地址中的 `target` → 地址中的 `format` → 已开启的客户端自动识别 → 订阅保存的默认格式。

原有 `?format=clash`、`?format=sing-box` 以及固定的同名默认格式继续返回节点列表，不会套用完整规则模板。需要模板中的 DNS、分组和路由规则时，使用 `target`，或开启自动识别并由受支持的客户端更新订阅。浏览器访问未必带有客户端标识，核对效果时可显式指定 `target`。

## 哪些入站会进入订阅

订阅只收录该用户已经获授权、已启用且有可用分享地址的入站；“不分享”的入站不会出现。顺序跟随入站的“订阅排序”，数字越小越靠前。

节点名称使用入站名称。HTTP / SOCKS 节点会携带对应节点用户的用户名和连接密码，HTTP 开启 TLS 时生成 HTTPS 代理链接；Shadowsocks SS2022 会生成完整连接密码。应直接导入订阅或分享链接，避免手工遗漏凭据。

预览为空时，依次检查用户入站授权、连接凭据、入站启用状态，以及“节点地址 / 入站监听地址 / 其他”的分享配置。监听通配地址 `0.0.0.0` 或 `::` 不能作为客户端连接地址。

用户停用、到期或订阅停用后，获取该订阅会被拒绝。停用订阅只影响获取入口；需要停止节点连接时，应停用用户并确认节点已经应用。

## 外部链接与订阅

在“用户”的编辑表单打开“链接”，可把第三方分享链接或远程订阅加入该用户生成的订阅。

| 字段 | 作用 |
| --- | --- |
| 添加外部链接 | 填写单条分享链接 |
| 添加外部订阅 | 填写远程 HTTP/HTTPS 订阅地址，主控获取后转换、合并 |
| 启用 | 控制此条内容是否加入 |
| 备注 | 记录来源或用途 |
| 名称前缀 | 外部订阅节点名称的前缀，便于区分来源 |
| 到期时间 | 超过时间后不再加入；留空表示不设置期限 |

外部订阅会显示最近拉取结果；失败时核对远端地址和访问条件后重新预览。手工链接按解析能力转换，并非任意客户端配置都能直接合并。

外部节点的服务、计量和期限由它们各自的提供方控制。加入 Plus 用户订阅不会把外部节点变成 Plus Agent 管理的服务器，也不会替其执行本地用户的限速、额度或停用操作。
