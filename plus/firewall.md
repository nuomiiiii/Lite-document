# 服务器防火墙 <PlusBadge />

本页仅适用于 Lite-Plus。入口位于后台“远程管理 → 防火墙”，按服务器管理主机入站规则，可分别配置 IPv4 与 IPv6、放行或拒绝端口、禁止 ping，以及设置入站默认拒绝。

## 使用前提

先开启站点远程管理和目标 Agent 的远程控制，并更新配套 Lite-Plus-agent，当前文档基线为 `0.0.2.4`。写操作会按页面要求验证管理员密码、2FA 或通行密钥；API Key 不能执行防火墙操作。

Linux 支持 nftables、iptables、UFW 和 firewalld；Windows 使用系统防火墙。Agent 需要具备管理目标主机防火墙的权限，Linux 通常以 root 运行。选择服务器后，先核对页面显示的后端、地址栈和支持状态。

没有检测到可用后端，且节点支持自动安装时，点击“安装 nftables”并完成验证即可。安装后由 Plus 应用规则，不会启用系统自带的 nftables 服务。页面未提供安装按钮时，按提示在主机安装后刷新。

## 添加与维护规则

1. 选择目标服务器，切换到 IPv4 或 IPv6 规则表。
2. 点击“新建”，填写动作、协议、端口和来源等字段。
3. 保存并按提示完成身份验证，等待下发状态变为“已应用到节点”。
4. 从实际客户端验证端口是否可达；云安全组、端口映射等也需放行对应端口。

<div class="plus-settings-table">

| 字段 | 填写方式 |
| --- | --- |
| 动作 | 放行或拒绝 |
| 协议 | TCP、UDP 或 TCP 与 UDP；选择两者时会拆为两条规则 |
| 端口 | 单个端口如 `443`、范围如 `10000-10100`，或 `*` 表示全部端口；不支持 `80,443` 这类逗号列表 |
| 来源 | 留空表示任意来源，也可填单个 IP 或 CIDR；必须与当前 IPv4 / IPv6 表匹配 |
| 优先级 | `1–9999`，默认 `100`，数字越小越先匹配 |
| 启用 | 关闭后保留记录，停止应用该规则 |
| 备注 | 便于识别用途，最多 120 字 |

</div>

同一地址栈中，协议、端口和来源完全相同的规则不能重复添加，即使动作或启用状态不同也会提示重复；需要调整时直接编辑原规则。不同来源的规则可以并存。每台服务器最多保存 200 条规则，TCP 与 UDP 拆分后分别计数。

编辑、启用、停用或删除规则后都会重新下发。规则保存在主控，节点保留原身份重装或重新连接后可再次下发。关闭站点远程管理不会撤销已经应用到主机的规则。

## 禁止 ping 与入站默认拒绝

页面上方分别提供“禁止 ping”和“入站默认拒绝”开关，每个开关同时设置 IPv4 与 IPv6；不可用的地址栈按页面状态处理。

“禁止 ping”用于阻止外部 ping 探测。“入站默认拒绝”开启后，未放行的入站流量会被丢弃，本机回环和已建立的连接继续保留。系统保留的管理端口及已放行的端口会出现在规则表中。

开启入站默认拒绝前，先点击“同步主机规则”，核对 SSH 等管理端口和需要对外提供的服务，再确认开启。保存时也会检查主机规则；如果检测到 Plus 无法驱动的 UFW / firewalld，页面会阻止开启并显示原因。

Linux 的系统保留项包含 SSH；Windows 还包含 RDP、WinRM 等管理端口。以当前服务器规则表为准，修改后同时检查下发状态和实际访问结果。

## 修改 SSH 端口

“SSH 端口”会读取主机实际监听端口。填写 `1–65535` 的新端口并确认后，Agent 会修改主机 sshd 配置、重载服务，并按新端口放行防火墙。

这项操作会改变 SSH 服务的实际监听端口。完成后使用新端口连接验证，并同步调整云安全组等外部规则。应用失败时查看页面错误及实际端口；Agent 会尝试回滚原 SSH 配置和相关规则。

## 同步与接管主机现有规则

“同步主机规则”会读取主机当前规则，扫描本身不会修改主机。可接管的简单入站规则可以勾选后点击“收进 Plus”，复杂规则链只展示，不会自动转换。

导入时可选择“收进 Plus 后停用主机上的对应原规则”。Plus 先保存并成功应用导入规则，再尝试停用原规则。停用失败或超时时，已导入的记录仍然保留，按页面提示重新扫描并处理原规则。

## 导入与导出

IPv4、IPv6 分别导出为 JSON 文件，文件名为 `lite-plus-firewall-v4.json`、`lite-plus-firewall-v6.json`。

导入会把文件中的规则追加到当前配置，不覆盖已有规则，并检查重复。导出文件也包含策略和 SSH 字段，但页面导入只导入规则；“禁止 ping”“入站默认拒绝”和 SSH 端口需要另外核对与设置。

## 与入站联动

在“节点管理 → 入站”创建或编辑入口时，勾选“同时放行该端口”，可按入站的地址栈、端口和协议生成放行规则。双栈入站同时处理 IPv4 与 IPv6；Shadowsocks 跟随所选 TCP / UDP，Hysteria2 和 TUIC 使用 UDP。

修改关联端口、协议或地址栈时会更新联动规则；停用入站会同步停用联动规则，关闭该选项或删除入站会移除对应规则。涉及防火墙变更时，仍需完成远程操作验证。

入站配置与防火墙各自下发。入站显示“已生效”后，还应在防火墙页确认规则已经应用。

## 下发状态

<div class="plus-settings-table">

| 状态 | 处理 |
| --- | --- |
| 待下发 | 配置已保存，等待发送 |
| 节点离线，已排队 | 等待原节点恢复连接 |
| 已发送到节点 | 等待 Agent 返回应用结果 |
| 已应用到节点 | 从实际客户端验证访问结果 |
| 下发失败 | 查看错误，核对权限、后端及规则后重试 |
| 节点无法应用 | 核对 Agent 版本、远程控制开关和系统支持情况 |

</div>
