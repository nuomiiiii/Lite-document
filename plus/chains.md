# 转发 <PlusBadge />

在“节点管理 → 转发”中选择线路入站和落地入站，即可让客户端连接线路节点，再由落地节点访问目标网站。Plus 会自动配置中转凭据、线路节点的出站和路由，无需分别创建。

例如：**客户端 → 线路入站 → 落地入站 → 目标网站**。多个线路入站可以共用落地，也可配置主备或多个落地自动选路。PPFlight 私有网络的完整示例见[内网中转落地](/plus/ppflight-private-network)。

## 创建前准备

1. 在线路节点创建客户端入口，在落地节点创建可用入站，具体字段见[入站与协议](/plus/inbounds)。
2. 确认线路节点能访问落地入站的分享地址和端口；使用私网时，落地的分享地址也应指向私网 IP。
3. 为落地配置对应证书和防火墙规则，并确认相关节点的配置已生效。创建转发不会自动放行端口。
4. 服务端与后台使用 Lite-Plus `0.2.0`，Agent 使用 Lite-Plus-agent `0.2.0.0`。线路节点的内核需支持落地协议：落地使用 VLESS + TLS 或 SS 时，线路入站可用 Xray；落地使用 Hysteria2、TUIC、AnyTLS 时，线路入站需选择 sing-box 内核，线路协议仍可使用 VLESS。

同一线路入站只能加入一条转发，不能同时作为这条转发的落地，也不能组成循环链路。已有手动路由引用该线路入站，或该入站已被手动出站作为“从入站导入”的来源时，需先调整或删除这些配置，再创建转发。落地入站可保留自己的手动路由。

## 新建转发

进入“节点管理 → 转发”，点击“新建”。

<div class="plus-settings-table">

| 字段 | 填写方式 |
| --- | --- |
| 名称 | 便于识别的名称，例如“精品入口走 Global” |
| 线路入站 | 选择客户端连接的入口，可多选；所选入口的流量按本条转发交给落地 |
| 选路方式 | “不启用”“主备”或“负载”，见下方说明 |
| 落地入站 | “不启用”时选择一个落地；“负载”时至少选择两个 |
| 主落地 | “主备”时优先使用的落地入站 |
| 备落地 | “主备”时选择另一个落地，或“直连（节点默认）” |
| 主备都不通时走直连 | 主、备均为落地入站时可选，默认关闭 |
| 均不通时走直连 | “负载”时可选，默认关闭 |
| 启用 | 本条转发的总开关，开启后下发应用 |

</div>

保存后，可在转发列表的“下发”列查看应用状态。首次创建时，再到“节点管理 → 概览”检查线路、落地节点均已返回“已生效”，然后从客户端重新连接验证出口；状态含义见[保存与节点生效](/plus/#保存与节点生效)。

### 单个落地

“选路方式”选择“**不启用**”，再选择一个落地入站。这表示不开启主备或多落地选路，**仍会执行单落地转发**；是否运行由“启用”开关控制。

例如，将“精品入口”作为线路入站、“Global 私网 VLESS”作为落地入站，保存后该入口的流量就会通过 Global 访问目标网站。

### 主备

选择“主备”，设置主落地和备落地。系统根据连通性探测优先使用主落地，主落地不可用时使用备落地。

备落地也可选择“直连（节点默认）”。若主、备均使用落地入站，可按需开启“主备都不通时走直连”。探测和切换需要时间，修改后应验证实际出口。

### 负载

选择“负载”，至少选择两个落地入站。系统根据探测延迟自动选路，优先使用延迟较低的可用落地；这不表示把流量平均分配给每个落地。

需要在所有落地均不可用时由线路节点自己出网，可开启“均不通时走直连”。

**直连表示线路节点直接访问目标网站，出口 IP 会回到线路节点。** 使用 PPFlight 内网中转来减少精品套餐流量时，开启直连回退后，这部分流量可能重新消耗精品机的公网套餐。

## 客户端用户与自动配置

多条转发和多个落地共用一个自动维护的中转专用账号，Plus 为其配置凭据并授权所需落地入站。这个账号不显示在普通用户、订阅列表或订阅模板的用户选择中，也不提供普通用户订阅，无需手动创建或分配套餐。

客户端用户仍在“节点管理 → 用户”中创建，授权所需的**线路入站**，并通过自己的订阅连接线路节点。无需把落地入站授权给普通用户；用户额度、期限、限速和在线 IP 仍按线路入口的用户配置执行。

自动生成的出站和路由不显示在后台普通“出站”“路由”列表中。需要调整线路、落地或选路方式时，回到“转发”编辑。

## 修改、停用与删除

<div class="plus-settings-table">

| 操作 | 效果 |
| --- | --- |
| 编辑转发 | 调整线路、落地和选路方式，只向实际配置发生变化的节点下发 |
| 修改落地入站 | 保存后同步关联转发，重新生成对应连接参数并下发 |
| 关闭“启用” | 停用该条转发，待节点应用；线路入站本身不会一并关闭，应核对剩余路由与实际出口 |
| 删除转发 | 清理关联自动路由和不再使用的自动出站，保留原有入站和普通客户端用户 |
| 删除参与转发的入站 | 解除相关关联；已无线路或落地时，转发记录也会清理 |

</div>

重复保存相同配置不会重新下发。增加一台线路节点时，已有线路与落地配置不变就不会重复下发；落地首次获得中转授权、连接参数变化或旧中转账号合并时，会向需要更新的节点下发。可结合转发列表的“下发”列和“概览”中的各节点结果检查。

已加入转发的线路入站不能再被手动路由或手动出站导入占用。需要按域名、IP、端口设置分流条件时，先解除该线路入站的转发，再按[出站与路由](/plus/forwarding)手动配置。

## 常见问题

<div class="plus-settings-table">

| 现象 | 检查内容 |
| --- | --- |
| 提示线路入站已占用 | 是否加入另一条转发，或被手动路由、导入出站引用 |
| 提示内核不兼容 | 线路内核是否支持落地协议；Hysteria2、TUIC、AnyTLS 落地需用 sing-box 线路入站 |
| 保存后无法连接 | 线路与落地是否均已生效，分享地址、证书、端口及防火墙是否正确 |
| 普通出站或路由列表找不到生成项 | 自动配置由“转发”统一管理，在该页面编辑 |
| 出口变成线路机 | 是否启用了直连备选或直连回退，落地是否可达 |

</div>
