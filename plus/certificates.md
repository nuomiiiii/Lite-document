# 节点证书 <PlusBadge />

本页仅适用于 Lite-Plus。“节点管理 → 证书”管理代理入站使用的节点证书；面板 HTTPS 仍在[内置 HTTPS](/security/https)中配置，两者分别设置。

页面分为“证书配置”和“签发管理”两个页签：前者管理各节点使用的证书，后者保存签发凭据，并申请、续签和管理根域名证书。

TLS 入站需要绑定同一节点的可用证书。Reality 使用独立密钥，不需要绑定这里的本机证书。

## 选择证书来源

新建证书默认选择“根证书下发”，也可按实际部署切换来源：

<div class="plus-settings-table">

| 来源 | 适用情况 | 私钥保存与续签 |
| --- | --- | --- |
| 根证书下发 | 申请根域名及通配域名证书，供多个节点使用不同子域名 | 主控生成并加密保存私钥，连同证书下发节点；在“签发管理”控制自动续签 |
| 主控申请 | 为单个节点申请指定域名证书 | Agent 在节点生成私钥，主控根据 CSR 签发证书链；在“证书配置”控制自动续签 |
| 节点文件 | 使用 1Panel、acme.sh 等工具已有的证书 | Agent 读取节点文件，申请与续期由原工具负责 |

</div>

## 保存签发设置

切换到“签发管理”，填写：

| 设置 | 用途 |
| --- | --- |
| Cloudflare API Token | 首次配置时必填，用于 DNS-01 验证；需要目标域名所属区域的读取权限和 DNS 记录的编辑权限 |
| ACME 邮箱 | 必填，用于 ACME 申请的联系邮箱 |

主控会根据申请的证书域名自动识别 Cloudflare 区域，无需填写 Zone ID。创建 Token 时，区域资源范围需包含要申请证书的域名所属区域。

点击“保存”。已保存的 Token 不会回显，留空保存会保留原值。

点击“清空”可删除已保存的 Cloudflare API Token 和 ACME 邮箱；再次申请或续期前，需重新填写并保存签发设置。

## 根域名证书与下发

需要让多个节点分别使用 `hk.example.com`、`jp.example.com` 等域名时，可先申请一张根域名证书，再下发到各节点：

1. 在“签发管理”保存上面的 Cloudflare Token 与 ACME 邮箱。
2. 在“根域名证书”区域填写根域名，例如 `example.com`，点击“申请根证书”。可分别添加多个不同域名。
3. 等待状态变为“已签发”。这张证书同时覆盖 `example.com` 和 `*.example.com`。
4. 切换到“证书配置”，点击“新建”，选择目标服务器，来源选“根证书下发”。
5. 选择已签发的根证书，在“子域名”填写该节点实际使用的域名，例如 `hk.example.com`，保存并检查下发结果。
6. 回到该节点的“入站”，选择这张证书，保存并等待“已生效”。其他节点重复第 4–6 步即可。

子域名必须在证书覆盖范围内：`example.com`、`hk.example.com` 可以使用，`a.hk.example.com` 不属于 `*.example.com` 的覆盖范围。域名还需解析到对应节点；申请和下发证书不会自动为节点创建 A / AAAA 解析。

入站分享策略使用“节点地址”时，会优先采用证书配置中的子域名。这里的根证书是用于网站和代理 TLS 的根域名证书，无需让客户端安装 CA 根证书。

在“签发管理”可查看根证书的状态、颁发者、有效期和错误，并执行“续期”或“重试申请”。根证书更新后会向关联节点重新下发；仍有节点证书引用时不能删除，应先处理关联记录。

## 主控申请证书

1. 切换到“证书配置”，点击“新建”，选择服务器并填写证书域名。
2. 证书来源选“主控申请”，保存。
3. Agent 在节点生成私钥和 CSR，主控用 Cloudflare DNS-01 向 Let's Encrypt 申请证书。
4. 主控将证书链下发给节点，检查证书状态、有效期、指纹及下发结果。
5. 回到“入站”，选择这张同节点证书，保存并等待“已生效”。

节点私钥由 Agent 本地保存，主控接收 CSR 并下发证书链。需要再次申请时，失败记录可点“重试申请”；已签发记录可点“续期”。

签发过程中，主控会自动写入 DNS 验证记录，等待 TXT 记录可查询后再提交验证。申请失败时，先查看列表中的错误，检查主控能否访问 Cloudflare、Let's Encrypt 及完成 DNS 查询，再重试申请。

| 状态 | 处理 |
| --- | --- |
| 等待 CSR | 检查 Agent 是否在线、是否为 Plus Agent，以及命令是否送达 |
| 已签发 | 核对域名、指纹与有效期，再检查入站应用结果 |
| 失败 | 查看错误，核对 Cloudflare Token 的权限与区域范围、证书域名和主控外网连接后重试 |

## 绑定节点已有证书

已有 1Panel、acme.sh 等工具管理的证书时，可以直接引用节点文件：

1. 在“证书配置”中点击“新建”，填写服务器和域名，证书来源选“节点文件”。
2. 分别填写节点上证书与私钥的完整路径，例如 `/opt/certs/fullchain.pem`、`/opt/certs/privkey.pem`。
3. 保存，等待 Agent 读取并返回指纹、颁发者和有效期。
4. 在同节点入站选择该证书，再检查下发状态。

这里的路径由目标节点的 Agent 读取，不是主控路径。Agent 在容器中运行时，填写容器内路径，并把宿主机证书目录挂载到该容器；Agent 进程必须拥有读取权限。

Agent 会定期检查文件变化并重新加载续期后的证书，也可在列表点击“重新读取”。证书的申请和续期仍由原有工具负责，Plus 的文件来源负责读取和应用。

## 自动续签与手动续期

“主控申请”和根域名证书默认开启“自动续签”。主控启动时检查一次，之后每 15 分钟检查；剩余有效期不足 30 天时发起续签，续签失败后至少间隔 6 小时再重试。

首次升级到支持自动续签的版本时，已有证书也会补入开启状态；升级后可按需要在对应列表中关闭。

<div class="plus-settings-table">

| 来源 | 设置位置与更新方式 |
| --- | --- |
| 主控申请 | 在“证书配置”列表切换“自动续签”；续签仍由节点生成 CSR，主控签发后下发证书链 |
| 根证书下发 | 在“签发管理”的根域名证书列表切换“自动续签”；节点记录跟随所选根证书更新，无需分别开启 |
| 节点文件 | 由原证书工具续期，Agent 检测文件变化并加载；列表不提供自动续签开关 |

</div>

自动续签需要有效的 Cloudflare Token、ACME 邮箱以及主控外网连接；单节点申请还需要 Agent 在线。清空签发设置后，应重新保存凭据才能继续申请或续签。需要提前更新时仍可点击“续期”，失败记录可查看错误后点击“重试申请”。

## 证书保存位置

“主控申请”和“根证书下发”的证书保存在对应节点的 Agent 目录中。使用官方安装方式、未修改配置文件位置时，默认路径如下：

| 系统 | 证书目录 |
| --- | --- |
| Linux | `/opt/lite-plus-agent/nodemgt/certs/` |
| Windows | `C:\Program Files\Lite-Plus\nodemgt\certs\` |
| macOS | `/usr/local/lite-plus-agent/nodemgt/certs/` |

目录中的证书文件名为 `{域名}.crt`，私钥文件名为 `{域名}.key`。“主控申请”按申请域名命名；根证书下发按根域名命名，例如使用 `example.com` 根证书的节点保存为 `example.com.crt` 和 `example.com.key`，不会为每个子域名单独申请一张证书。

如果通过 `--config` 指定了其他配置文件位置，证书目录也随配置文件位置变化：配置文件在哪个目录，证书就保存在该目录下的 `nodemgt/certs/` 中。

## 迁移与备份

根域名证书的证书链和加密私钥随主数据库保存，恢复时应使用包含实例密钥的完整备份。“主控申请”在节点生成的私钥、节点文件来源的证书和 Agent 本地状态仍需单独保留。

更换节点或重装到空目录后，应重新核对证书路径、指纹及入站绑定。根证书来源可重新下发；其他来源需恢复节点文件或重新申请，不能只根据主控列表的旧状态判断证书可用。
