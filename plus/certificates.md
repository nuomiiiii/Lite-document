# 节点证书 <PlusBadge />

本页仅适用于 Lite-Plus。“节点管理 → 证书”管理代理入站使用的节点证书；面板 HTTPS 仍在[内置 HTTPS](/security/https)中配置，两者分别设置。

TLS 入站需要绑定同一节点的可用证书。Reality 使用独立密钥，不需要绑定这里的本机证书。

## 主控申请证书

### 保存签发设置

在证书页的“主控申请证书”区域填写：

| 设置 | 用途 |
| --- | --- |
| Cloudflare API Token | 在域名所属区域完成 DNS-01 验证，需要对应 DNS 记录的读取与编辑权限 |
| Cloudflare Zone ID | 域名所属的区域 ID |
| ACME 邮箱 | 用于 ACME 申请的联系邮箱 |

点击“保存签发设置”。已保存的 Token 不会回显，留空保存会保留原值。

### 发起申请

1. 点击“新建”，选择服务器并填写证书域名。
2. 证书来源选“主控申请”，保存。
3. Agent 在节点生成私钥和 CSR，主控用 Cloudflare DNS-01 向 Let's Encrypt 申请证书。
4. 主控将证书链下发给节点，检查证书状态、有效期、指纹及下发结果。
5. 回到“入站”，选择这张同节点证书，保存并等待“已生效”。

节点私钥由 Agent 本地保存，主控接收 CSR 并下发证书链。需要再次申请时，失败记录可点“重试申请”；已签发记录可点“续期”。

| 状态 | 处理 |
| --- | --- |
| 等待 CSR | 检查 Agent 是否在线、是否为 Plus Agent，以及命令是否送达 |
| 已签发 | 核对域名、指纹与有效期，再检查入站应用结果 |
| 失败 | 查看错误，核对 Cloudflare Token、Zone ID、域名和主控外网连接后重试 |

## 绑定节点已有证书

已有 1Panel、acme.sh 等工具管理的证书时，可以直接引用节点文件：

1. 点击“新建”，填写服务器和域名，证书来源选“节点文件”。
2. 分别填写节点上证书与私钥的完整路径，例如 `/opt/certs/fullchain.pem`、`/opt/certs/privkey.pem`。
3. 保存，等待 Agent 读取并返回指纹、颁发者和有效期。
4. 在同节点入站选择该证书，再检查下发状态。

这里的路径由目标节点的 Agent 读取，不是主控路径。Agent 在容器中运行时，填写容器内路径，并把宿主机证书目录挂载到该容器；Agent 进程必须拥有读取权限。

Agent 会定期检查文件变化并重新加载续期后的证书，也可在列表点击“重新读取”。证书的申请和续期仍由原有工具负责，Plus 的文件来源负责读取和应用。

## 迁移与备份

完整备份主控数据还不够：节点上的私钥、证书文件和 Agent 状态需单独保留。更换节点或重装到空目录后，应重新核对证书路径、指纹及入站绑定，不能只根据主控列表的旧状态判断证书可用。
