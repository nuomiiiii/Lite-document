# 出站与路由 <PlusBadge />

本页仅适用于 Lite-Plus。入站接收客户端连接，出站决定流量发往哪里，路由负责把符合条件的流量送到指定出站。

## 节点出站地址族

在“节点管理 → 概览”按服务器设置“出站地址族”，控制该节点代理连接外部目标时使用的地址族。同一节点的 Xray 与 sing-box 共用此设置。

<div class="plus-settings-table">

| 选项 | 行为 |
| --- | --- |
| 双栈 | 默认值，不强制指定出站地址族 |
| 仅 IPv4 | 只使用 IPv4 连接目标 |
| 仅 IPv6 | 只使用 IPv6 连接目标 |
| IPv4 优先 | 优先 IPv4，失败后尝试 IPv6 |
| IPv6 优先 | 优先 IPv6，失败后尝试 IPv4 |

</div>

保存后等待节点“已生效”，再验证实际出口。选择仅 IPv4 / IPv6 前，确认目标与节点具备对应网络。

该设置与入站监听地址栈、Agent 连接主控的地址偏好分别配置。节点选择非“双栈”时，会覆盖出站单独设置的直连域名策略；需要按出站分别控制解析时，先将节点恢复为“双栈”。

## 出站

每个节点默认带有 `direct`（直连）和 `block`（阻断），无需手工创建。需要额外代理出口或链式代理时，进入“节点管理 → 出站”点击“新建”。

<div class="plus-settings-table">

| 字段 | 说明 |
| --- | --- |
| 服务器 | 出站配置所属节点 |
| 出站标签 | 同一节点必须唯一；不能使用保留名称 `direct`、`block` |
| 协议 | VLESS、VMess、Trojan、Shadowsocks、AnyTLS、SOCKS、HTTP，以及直连和阻断类型 |
| 地址与目标端口 | 出口服务器的可达地址和端口 |
| 凭据 | 按目标协议填写 UUID、用户名、密码或加密方法 |
| 传输与安全 | 与目标入口的 TCP、WebSocket、gRPC、TLS 或 Reality 等配置一致 |
| Shadowsocks 网络 | TCP 与 UDP、仅 TCP 或仅 UDP，默认两者都启用，与目标入口保持一致 |
| 前置出站 | 先经所选出站再连接目标，用于链式代理；没有需要时保持“无” |
| 域名策略 | 直连类型的域名解析策略，可选 AsIs、UseIP、UseIPv4、UseIPv6；节点出站地址族为“双栈”时按此项执行 |

</div>

### 从已有配置导入

- **粘贴分享链接**：支持从 `vless://`、`vmess://`、`trojan://`、`ss://`、`anytls://` 自动填入目标地址、传输和安全参数。
- **从入站导入**：选择已有入站作为转发目标；该入站应先设置可用的分享地址。HTTP 入站会带入首组账户的用户名和密码；Shadowsocks 会带入 TCP / UDP 网络选项，SS2022 还会组合服务器密钥与用户密钥，生成目标所需的完整密码。

导入后检查凭据、节点归属、标签和前置出站，再保存。导入只是填写表单，保存并收到节点确认后才应用。

导入 VLESS 目标或切换内核时，Flow 会按目标内核支持的选项调整。sing-box 使用 `xtls-rprx-vision`，从 Xray 导入的 Vision `udp443` 形式会转换为此值；重新核对目标入口的配置后再保存，见[VLESS Vision](/plus/inbounds#vless-vision)。

Shadowsocks 的网络、加密方法和密码必须与目标入口一致，SS2022 不应只填写 UUID。配套 Agent `0.0.2.4` 支持应用出站网络选项；导入后仍应检查节点应用结果。编辑已有出站并切换协议时，重新核对新协议的凭据、传输和安全配置；非 Shadowsocks 出站无需填写 Shadowsocks 加密方法。

## 路由

进入“节点管理 → 路由”，新建规则并选择所属服务器和目标出站。

<div class="plus-settings-table">

| 字段 | 说明与示例 |
| --- | --- |
| 入站 | 留空表示对该节点全部入站生效，也可限定到一个入口 |
| 出站 | 选择 `direct`、`block` 或该节点已创建的额外出站 |
| 优先级 | 数字越小越先匹配，命中后停止继续匹配 |
| 域名 | 逗号分隔；普通域名按后缀匹配，也支持 `geosite:cn` 等规则 |
| IP | IP / 网段或 Geo 规则，例如 `geoip:private`、`geoip:cn` |
| 网络 | 未选择时不限，可按需选择 TCP、UDP 或 TCP 与 UDP |
| 目标端口 | 例如 `80,443`、`1000-2000` |
| 来源 IP | 客户端源地址，多个值用逗号分隔 |
| 探测协议 | 默认“不限”；选择 HTTP、TLS、QUIC、BitTorrent 等条件时，需先在入站开启流量探测 |

</div>

### 匹配方式

同一条规则中，不同字段之间是“且”：域名、IP、网络、端口、探测协议和来源 IP 等已填写条件必须同时命中。同一字段中用逗号分隔的多个值是“或”，命中其中一个即可；未填写的条件不限制。

域名字段支持以下写法：

<div class="plus-settings-table">

| 写法 | 示例 | 匹配范围 |
| --- | --- | --- |
| 普通域名 | `example.com` | 该域名及其子域名 |
| 域名后缀 | `domain:example.com` | 该域名及其子域名 |
| 完整域名 | `full:example.com` | 仅该域名 |
| 关键词 | `keyword:example` | 域名中包含该关键词 |
| 正则 | `regexp:^api[.]example[.]com$` | 按正则表达式匹配，也可使用 `regex:` 前缀 |
| GeoSite | `geosite:cn` | 对应域名规则集 |

</div>

节点会按规则需要准备 Geo 数据。首次应用涉及 GeoIP / GeoSite 的规则时，应等待数据准备和节点回执；失败时查看“下发”错误和 Agent 日志。

入站选择“双栈”时，规则仍选择原入站即可，无需为 IPv4 和 IPv6 分别创建相同规则。路由匹配修复需要配套更新 Agent，保存后再验证实际出口。

### 示例：中国域名或中国 IP 直连

分别建立两条规则，目标出站都选“直连（节点默认）”：

<div class="plus-settings-table">

| 规则 | 域名 | IP |
| --- | --- | --- |
| 中国域名直连 | `geosite:cn` | 留空 |
| 中国 IP 直连 | 留空 | `geoip:cn` |

</div>

两条规则分别匹配中国域名或中国 IP。若把 `geosite:cn` 和 `geoip:cn` 填在同一条规则中，就要求域名和目标 IP 同时满足，不能达到二者任一命中即直连的效果。将更具体的阻断或代理规则排在前面，保存并等待节点“已生效”。

### 示例：拦截广告域名

1. 在对应入站开启流量探测，保留 HTTP、TLS 等探测类型。
2. 新建路由，选择同一服务器；需要限定入口时选择该入站。
3. 域名填写 `geosite:category-ads-all`，出站选择“阻断（节点默认）”。
4. 设置较靠前的优先级，保存并等待“已生效”。

需要经额外代理转发时，先创建出站，再在规则中选择它。入站、出站与规则应属于同一节点，不能只凭其他节点的同名标签选路。
