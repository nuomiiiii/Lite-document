# 出站与路由 <PlusBadge />

本页仅适用于 Lite-Plus。入站接收客户端连接，出站决定流量发往哪里，路由负责把符合条件的流量送到指定出站。

需要直接把线路入站交给落地入站时，可使用[转发](/plus/chains)，由 Plus 自动维护中转凭据、出站和路由，并支持主备或多个落地选路。本页介绍手动配置，适合按域名、IP、端口等条件设置分流。

完整的两机配置示例见 [PPFlight 内网中转落地](/plus/ppflight-private-network)：客户端连接精品优化机，优化机通过私网把流量交给 Global，再由 Global 访问目标网站。

## 节点出站地址族

在“节点管理 → 概览”按服务器设置“出站地址族”，控制该节点代理连接外部目标时使用的地址族。同一节点的 Xray 与 sing-box 共用此设置。

<div class="plus-settings-table">

| 选项 | 行为 |
| --- | --- |
| 双栈 | 默认值，不强制指定出站地址族 |
| 仅 IPv4 | 只使用 IPv4 连接目标 |
| 仅 IPv6 | 只使用 IPv6 连接目标 |
| IPv4 优先 | 优先 IPv4，失败后尝试 IPv6 |
| IPv6 优先 | 优先 IPv6，失败后尝试 IPv4 |

</div>

保存后等待节点“已生效”，再验证实际出口。选择仅 IPv4 / IPv6 前，确认目标与节点具备对应网络。

使用当前配套 Agent 时，开启用户在线 IP 限制后，出站地址族设置对 TCP 与 UDP 连接也生效。更新后可分别验证两种网络的实际出口。

该设置与入站监听地址栈、Agent 连接主控的地址偏好分别配置。节点选择非“双栈”时，会覆盖出站单独设置的直连域名策略；需要按出站分别控制解析时，先将节点恢复为“双栈”。

## 出站

每个节点默认带有 `direct`（直连）和 `block`（阻断），无需手工创建。需要额外代理出口或链式代理时，进入“节点管理 → 出站”点击“新建”。

<div class="plus-settings-table">

| 字段 | 说明 |
| --- | --- |
| 服务器 | 出站配置所属节点 |
| 出站标签 | 同一节点必须唯一；不能使用保留名称 `direct`、`block` |
| 协议 | VLESS、VMess、Trojan、Shadowsocks、Hysteria2、TUIC、AnyTLS、SOCKS、HTTP，以及直连和阻断类型 |
| 内核 | Hysteria2、TUIC、AnyTLS 选择 sing-box 后可用；Xray 只显示其支持的协议 |
| 地址与目标端口 | 出口服务器的可达地址和端口 |
| 凭据 | 按目标协议填写 UUID、用户名、密码或加密方法 |
| 传输与安全 | 与目标入口的 TCP、WebSocket、gRPC、TLS 或 Reality 等配置一致 |
| Shadowsocks 网络 | TCP 与 UDP、仅 TCP 或仅 UDP，默认两者都启用，与目标入口保持一致 |
| 前置出站 | 先经所选出站再连接目标，用于链式代理；没有需要时保持“无” |
| 域名策略 | 直连类型的域名解析策略，可选 AsIs、UseIP、UseIPv4、UseIPv6；节点出站地址族为“双栈”时按此项执行 |

</div>

### 从已有配置导入

- **粘贴分享链接**：支持从 `vless://`、`vmess://`、`trojan://`、`ss://`、`anytls://`、`hysteria2://`（或 `hy2://`）、`tuic://` 自动填入目标地址、传输和安全参数。
- **从入站导入**：选择已有入站作为转发目标；该入站应先设置可用的分享地址。HTTP 入站会带入首组账户的用户名和密码；Shadowsocks 会带入 TCP / UDP 网络选项，SS2022 还会组合服务器密钥与用户密钥。Hysteria2 会带入连接密码，TUIC 会同时带入 UUID 和连接密码。

导入后检查凭据、节点归属、标签和前置出站，再保存。导入只是填写表单，保存并收到节点确认后才应用。

已作为“转发”线路的入站不能再作为手动导入的来源。反过来，入站已有手动导入出站引用时，也需先解除引用再加入转发。转发自动生成的出站不显示在后台普通出站列表中，请到“转发”编辑。

### Hysteria2 与 TUIC 出站

选择 sing-box 后再选择 Hysteria2 或 TUIC，填写目标地址和端口。两者使用 QUIC 与 TLS，目标应能通过 UDP 到达，SNI 与目标证书保持一致。

<div class="plus-settings-table">

| 协议 | 凭据 |
| --- | --- |
| Hysteria2 | 填写目标入口的连接密码 |
| TUIC | 同时填写目标入口的 UUID 和连接密码 |

</div>

使用 Lite-Plus `0.1.6` 与 Lite-Plus-agent `0.0.3.2` 配套配置。导入分享链接后也应核对凭据与 TLS 参数，保存并等待“已生效”，再测试转发与路由。

### 其他协议的导入检查

导入 VLESS 目标或切换内核时，Flow 会按目标内核支持的选项调整。sing-box 使用 `xtls-rprx-vision`，从 Xray 导入的 Vision `udp443` 形式会转换为此值；重新核对目标入口的配置后再保存，见[VLESS Vision](/plus/inbounds#vless-vision)。

Shadowsocks 的网络、加密方法和密码必须与目标入口一致，SS2022 不应只填写 UUID。配套 Agent `0.0.2.4` 及以上支持应用出站网络选项；导入后仍应检查节点应用结果。编辑已有出站并切换协议时，重新核对新协议的凭据、传输和安全配置；非 Shadowsocks 出站无需填写 Shadowsocks 加密方法。

## 路由

进入“节点管理 → 路由”，新建规则并选择所属服务器和目标出站。

已加入“转发”的线路入站不能再被手动路由占用。需要切换为手动分流时，先从转发中移除该线路入站；原有手动路由也需先调整，才能将对应入口加入转发。转发生成的路由不显示在后台普通路由列表中。

<div class="plus-settings-table">

| 字段 | 说明与示例 |
| --- | --- |
| 入站 | 选择此规则作用的入站；已被“转发”占用的线路入站不可选 |
| 选路方式 | “不启用”或“主备”；手动路由不提供“负载”选项 |
| 出站 | “不启用”时选择 `direct`、`block` 或该节点已创建的额外出站 |
| 主出站 | “主备”时优先使用的出站 |
| 备出站 | “主备”时选择另一个出站，或“直连（节点默认）”；不能与主出站相同 |
| 主备都不通时走直连 | 备出站为额外出站时可选；备出站已选直连时不显示 |
| 优先级 | 数字越小越先匹配，命中后停止继续匹配 |
| 域名 | 逗号分隔；普通域名按后缀匹配，也支持 `geosite:cn` 等规则 |
| IP | IP / 网段或 Geo 规则，例如 `geoip:private`、`geoip:cn` |
| 网络 | 未选择时不限，可按需选择 TCP、UDP 或 TCP 与 UDP |
| 目标端口 | 例如 `80,443`、`1000-2000` |
| 来源 IP | 客户端源地址，多个值用逗号分隔 |
| 探测协议 | 默认“不限”；选择 HTTP、TLS、QUIC、BitTorrent 等条件时，需先在入站开启流量探测 |

</div>

### 主备出站

在路由表单的“目标”页签，将“选路方式”设为“主备”，再选择主出站和备出站。命中这条规则的流量优先走主出站，主出站探测失败后改走备出站；入站、匹配条件和优先级仍按本条规则执行。

例如，先在同一节点创建 `exit-primary` 和 `exit-backup` 两个代理出站，再创建路由，选择对应入站、主出站 `exit-primary`、备出站 `exit-backup`。按需在“匹配”页签填写域名、IP、端口等条件，保存并等待节点“已生效”。路由列表会显示主、备出站名称及选路方式。

备出站也可直接选择“直连（节点默认）”。备出站选择额外出站时，可开启“主备都不通时走直连”，让两者均探测失败后由当前节点直接访问目标网站。直连时出口 IP 会变为当前节点，探测和切换需要时间，保存后应验证实际出口。

选择“不启用”仍会执行该路由，只使用“出站”指定的一个出口。改回“不启用”或删除路由时，Plus 会清理该路由自动生成的选路出站组，保留手动创建的主、备出站。自动出站组不显示在普通出站列表中，调整主备应编辑对应路由。删除主出站或备出站时，引用它的路由和对应自动出站组也会一并删除。

### 匹配方式

同一条规则中，不同字段之间是“且”：域名、IP、网络、端口、探测协议和来源 IP 等已填写条件必须同时命中。同一字段中用逗号分隔的多个值是“或”，命中其中一个即可；未填写的条件不限制。

域名字段支持以下写法：

<div class="plus-settings-table">

| 写法 | 示例 | 匹配范围 |
| --- | --- | --- |
| 普通域名 | `example.com` | 该域名及其子域名 |
| 域名后缀 | `domain:example.com` | 该域名及其子域名 |
| 完整域名 | `full:example.com` | 仅该域名 |
| 关键词 | `keyword:example` | 域名中包含该关键词 |
| 正则 | `regexp:^api[.]example[.]com$` | 按正则表达式匹配，也可使用 `regex:` 前缀 |
| GeoSite | `geosite:cn` | 对应域名规则集 |

</div>

节点会按规则需要准备 Geo 数据。首次应用涉及 GeoIP / GeoSite 的规则时，应等待数据准备和节点回执；失败时查看“下发”错误和 Agent 日志。

入站选择“双栈”时，规则仍选择原入站即可，无需为 IPv4 和 IPv6 分别创建相同规则。路由匹配修复需要配套更新 Agent，保存后再验证实际出口。

### 示例：中国域名或中国 IP 直连

分别建立两条规则，目标出站都选“直连（节点默认）”：

<div class="plus-settings-table">

| 规则 | 域名 | IP |
| --- | --- | --- |
| 中国域名直连 | `geosite:cn` | 留空 |
| 中国 IP 直连 | 留空 | `geoip:cn` |

</div>

两条规则分别匹配中国域名或中国 IP。若把 `geosite:cn` 和 `geoip:cn` 填在同一条规则中，就要求域名和目标 IP 同时满足，不能达到二者任一命中即直连的效果。将更具体的阻断或代理规则排在前面，保存并等待节点“已生效”。

### 示例：拦截广告域名

1. 在对应入站开启流量探测，保留 HTTP、TLS 等探测类型。
2. 新建路由，选择同一服务器；需要限定入口时选择该入站。
3. 域名填写 `geosite:category-ads-all`，出站选择“阻断（节点默认）”。
4. 设置较靠前的优先级，保存并等待“已生效”。

需要经额外代理转发时，先创建出站，再在规则中选择它。入站、出站与规则应属于同一节点，不能只凭其他节点的同名标签选路。
